# Z12：停车分析读取测量与正文优化

日期：2026-10-19。状态：本地实现、相关测试通过；未提交、未推送、未部署。基线提交 `8f5fc69`。

## 先测量，再修改

修改前先运行合成归档探针。90 天历史，每 5 分钟一条新鲜状态，扣除两天断档，共 25,344 条；查询 2026-08-15 一天。首次测量保存在同名 JSON 的 `original_before_implementation`。

最终代码分别回放原始全正文路径（`--full-payload` 仅关闭正文筛选）和优化路径，各三轮。表中耗时为端到端查询中位数，包含事件读取、归档读取、临时投影、停车计算和地点命名，不含造数。正文数为实际 payload 解压解码次数；元数据数为归档流返回的记录数，不是数据库物理页 I/O。

本地 macOS/arm64，未限制 CPU；调度和缓存会造成波动。这些数值不是生产配额下的延迟保证。探针只使用自动清理的临时合成目录，没有读取实车归档或发送通知。

## 修改与边界

- 按相邻行程构造可能与查询日期相交的完整停车窗口；未知起止保持无界，不套固定天数上限。只省略窗口外的状态、位置正文。旧观测片段仍保留原日期前后 padding。
- 同时考虑车辆时间、采集时间。远晚于查询日采集、但车辆时间落在相关停车窗口的缓存仍读取正文，不能掩盖里程或位置冲突。
- 所有时间元数据继续进入原临时投影，保留重复、修订、倒退、首条观测、最后新鲜时间及最后采集时间。事件 ID、起止、跨日分类、缺口、充电、耗电、地点、孤立片段不变，计算版本仍为 v6。
- `ArchiveReader.iter_records` 默认行为不变。停车调用新增可选 `payload_when`，省略正文时返回 `None`。读取上限仍按元数据计数，冻结水位、分片校验、账号车辆隔离、取消检查继续执行。窗口查找使用二分，避免每条记录线性扫描所有行程窗口。
- 历史数据只读，没有持久缓存、数据迁移或归档重写。

**剩余成本：** 缺边界时仍遍历原历史范围的时间元数据；`UsageEvents` 仍读取历史事件。真正覆盖整段归档的停车仍解码全部必要正文。本次减少无关正文读取、解码及状态投影，不保证所有短日期查询都有固定扫描量。无行程长停车耗时前后接近，未声称该场景加速。

## 验证与复现

先增加读取量回归、确认修改前失败，再实现筛选。最终 216 项相关测试通过，23.457 秒：停车全部专项、归档读取/容量、取消、分析接口、用车报告、周期汇总、充电分析、快照归档。

新回归包含七种集成场景的全响应对照，以及查询日之外采集、旧车辆时间落在停车段的矛盾里程证据。另用固定随机种子执行 60 组 v6 全量/筛选对照，混合位置变化、重复、修订、倒退、无效时间、充电状态。归档专项验证省略正文仍保留元数据语义、读取上限、冻结水位。

没有前端改动，未运行浏览器或移动端测试；生产验证留在发布阶段。同名 JSON 保存原始测量、逐轮耗时/计数、响应哈希、环境、五个代码及测试文件 SHA-256。
