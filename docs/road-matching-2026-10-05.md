# 轻量路网匹配接入：最近道路＋最短路径

用户选择评分表第一方案。接入最近道路＋最短路径算法，采用经过对比的标准库实现；不安装重路由服务，不采用 HMM。用户已授权提交、部署；发布结果与回滚见本次发布记录。未授权推送。

## 使用

本地行程页照常查询日期／行程并显示位置。API `/api/tracks` 增加 `road_matching`，原 observations/segments/gaps/quality 原样保留。匹配成功沿道路画，未匹配或未连通部分仍画源点虚线，全部源点和回放保留。说明明确为算法推断、未经实走确认。没有可用路网时保留原显示。

运行只需 Python 3.9+ 标准库、SQLite RTree。区域道路库从本机已有 OSM 快照离线构建，位于会话文件同级 `road-networks/*.sqlite3`，本机四库约10MB。库只读；替换库会使结果缓存失效。此路径不在 Git 中；迁移服务器时单独安装区域数据库至服务用户的会话目录，并让服务用户可读。没有后台下载器，不向第三方上传车辆点。

重新建库：

```sh
python3 -m zeekr_control.road_network --osm /path/to/region-osm.json --out /path/to/ZeekrControl/road-networks/region.sqlite3
```

输入是 Overpass OSM JSON (`elements`含道路和节点)，不是位置采样。仅构建驾驶道路，排除步道及明确 access/motor_vehicle/motorcar=no 的道路，保留单行、反向单行与环岛方向；无禁转关系。离线输入100MB上限，区域应按需划分。现有区域快照为原试验覆盖，不等于全国路网，也不保证区域内道路完整。道路数据来源：[OpenStreetMap](https://www.openstreetmap.org/copyright)，ODbL 1.0；绘图保留来源标识。

## 边界与开销

- 50米候选半径、最多12个方向候选。投影最近道路，再按单行图求最短路径。双向同距离方向候选优先与前点连接较短者；首点方向并无真实朝向证据。同向同路段后退20米内按投影抖动处理。
- 局部平面投影，保留实际折点，裁切到源点在路上的投影位置。最短路径不是实际走法保证；缺少观测时可能选错道路，尤其绕路、禁转或平行道路。
- TrackStore 先定义可信片段；每片段独立处理。未知坐标系、GCJ-02、未可信、未可绘、缓存时间缺失或不递增会再次切断。缓存状态时间不被当GPS采集时刻，不从位置计算实车速度。
- 一个工作进程，nice10；Linux 内存地址空间256MB、CPU6秒、墙钟8秒。macOS不设置不兼容的地址空间限制，保留CPU和墙钟限额。限额在 exec 后设置，避免 threaded web 的 preexec_fn 死锁风险。匹配时不持有 App 全局锁。
- 每次1500有效源点、最多8个道路库、每库64MB、输出40000顶点和1.5MB上限；超过上限整次回退原连线。路径搜索每起点10公里、最多24起点缓存，超限不伪造连接。
- 复用最近两次匹配；源片段或地图mtime/size变化使缓存失效。繁忙、超时、故障均无损回退，页面提供重试路网。无路网、超时、未匹配不算完成路线。
- 资源数字仅为工作进程，不是整个服务总内存。当前服务器临时隔离跑六条路线，每条三次，含解释器启动/选库/加载/输出：峰值39.1MB，最慢路线中位0.66秒。临时文件已清，生产没有改变。
- 不重算里程、费用、行程时间；没有修改通知地图或遥测存储。
