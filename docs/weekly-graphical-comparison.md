# 周报／月报：紧凑增减图

用户确认的紧凑预览对应网页版周报／月报。首行双列展示核心变化与耗电／充电／实付；第二行展示每日里程差额与出发时段；下方横排归档日期、片段次数与按需读取的地点。结束记录使用可点选柱图，点选后查看 SOC 端点及原始明细。保留日期、事件类型、片段筛选、翻页、错误保留与按需自动洞察。

不再展示每条记录平均里程、单日记录最高、片段已观测里程、归档读取次数、有效不同车辆时间、重复读取、修订读取、旧值或异常观测这八项。原始数据及后台统计不删除。

## 口径

核心增减条以零为中心，左减右增，不代表好坏。两列共用环比刻度，按实际最大涨跌自动扩展，不截断超过 60% 的变化；同时显示两期原值和已知差额。进行中周期、样本不足、上期为零不计算百分比。

每日里程按星期或月内日期对齐，画本期减上期的已记录差额。刻度包含零，有负差额时显示负区；全正数据不保留空的负区。未来日期、上期无对应日、任一期未知不补成零；已知零差额单独标记。两期任一日含片段时使用警示色。点击差额未知的日期仍可查看本期有效行程。

实付沿用稳定账号／车辆的一份账单快照，按账单日期归期，排除未来账单；仅 `actual_cents`，不含停车费或日常支出，不推算耗电成本。没有已录金额为未知，免费账单为零；金额待补或充电事件未关联账单时不算实付环比。查询继续复核身份及个人记录版本。

地点默认显示前两项及非零的未知地点，其余可展开；归档日期不等于全天覆盖。记录柱按同类里程或充电观测分钟共享刻度，不混比单位。SOC 图只连接两个已知端点，不代表中间过程。企业微信周期推送图片、发送时间及后端模型不随此次前端改动变化。

## 验证

`tests/usage_report_analysis.cjs` 检查共用刻度、正负与零轴几何、日差额、未知／未来、正负域。`DESKTOP_ONLY=1 node tests/ui_usage_reports.cjs` 检查移除项、双列顺序、实付、负差额、已知零差额、未知日期、月内无对应日、记录点选、筛选和错误保留，以及明暗主题、桌面宽度、缩放和对比度。`tests/ui_research_simplification.cjs` 保留自动洞察的按需展开验证。发布以生产匹配候选及完整输入哈希为准。
