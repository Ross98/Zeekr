## 根因与修改

月报只需要观测日期，旧代码却遍历整月全部元数据；冻结水位的带作用域 MAX(id) 又会扫描该作用域的覆盖索引。复测旧版完整月份峰值仍为 128.00 MiB、max=92；复杂月份为 128.00 MiB、max=140，均不能因 OOM=0 而通过。

新读取按北京时间逐日索引定位，只取每个有数据日期的首条时间；冻结水位改用追加表的全局 id 上界，实际读取仍限制账号、车辆、时间和水位。缺失日期、跨月、尾界、后插入记录与归档替换仍分别处理。无需改表、删历史数据或重放已发送报表。

复杂图片同时暴露 CPU 热点。最短路现在在目标距离确定后暂停，后续目标继续原搜索前沿；同一图片的相邻片段复用当前路网，切换区域时关闭旧连接。绘制批量填充不透明内部像素，跳过零覆盖范围，并用整数求和重写固定两倍插值。原方向约束、10km 搜索上限、片段隔离、6 秒 CPU 与 45 秒图片超时均保留。

原版与最终版的 1500 点复杂路线对照：9940 条背景道路、2328 条匹配线、完整几何结果与 PNG 字节均一致。此对照在本机执行，用于证明输出一致，不替代服务器资源验收。

容量工具增加硬限额余量门槛，默认至少 20%，且 max、oom、oom_kill 必须为 0。缺失配额、失败工作进程和不完整结果均不能通过。工具纳入发布白名单和完整输入指纹，避免测试依赖未随候选安装。

## 场景与判定

每轮新建 267840 条鲜活合成记录，10 秒一条，覆盖 31 天；验后独立核对 reads 与 payloads 均为 267840。每月另含 248 次行程、31 次充电、部分记录和未计价账单，生成浅、深两套月报 PNG。行程图片为 1500 点、30 个独立片段、9940 条道路；采集在图片运行时继续归档。三轮均断言 31 个观测日、archive_limited=false、事件数及 PNG 有效，没有缩减输入。

三轮复用同一只读源码，使用不同的全新合成库；为增加竞争，三组验收与最终全量回归并发执行。每个 workload 使用真实服务用户、生产原配额的独立 systemd cgroup，禁网络、禁 swap。仅驱逐各自新建 SQLite 文件的缓存，没有清理生产或全局缓存。月报、采集各为 128 MiB／15% CPU；Web 为 256 MiB／25% CPU、MemoryHigh 192 MiB。
