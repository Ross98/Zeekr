# 完整车辆快照年度归档

用户确认：存放服务器硬盘，按自然年分档，旧年保留。没有自动删除期限。

## 存什么、什么时候存

- 从启用后每次成功取得车辆状态开始，保存完整 JSON 响应的所有字段、类型及值，含新增/未知字段；不只是 27 项充电参数。
- 后台采集和手动刷新共用 `SnapshotStore.publish()` 入口；普通页面状态轮询和读取最新快照不新增归档。
- 保留车辆 `state_time`、云端读取 `fetched_at`、本次处理 `observed_at`、账号作用域摘要、车辆摘要与读取来源。作用域摘要不是令牌；归档不接收 session、SSH 密码或 webhook。
- 相同 JSON 内容按 SHA-256 去重并 gzip 无损压缩；每次不同读取仍记时间。相同元数据的重试幂等；不是每分钟复制重复正文。
- 时间倒退、同时间内容修正、重复缓存、缺车辆时间的合法响应仍归档。原有最新快照选择规则和状态判定不变。
- 继续沿用后台约 60 秒、确认稳定停车后 300 秒的采集节奏；暂停、限流和故障期间没有虚构记录。一次轮询不保证车辆产生一次更新。
- 既有零散样本不会自动回填为分钟级历史，首次启用前未留存的完整数据无法还原。

## 自然年与目录

以**本次观测时间（北京时间 UTC+8）**决定分档，不使用可能陈旧或缺失的车辆时间。

```text
<服务私有数据目录>/snapshot-archive/
  2026/
    09.sqlite3
    10.sqlite3
    ...
  2027/
    01.sqlite3
```

年目录是逻辑归档单位，内部每月一个 SQLite 文件，避免全年数据挤入一个大文件而触碰服务文件大小上限。月份无记录时不创建空文件。
跨年自动新建目录，旧年不删除、不压缩覆盖、不修改已归档正文。没有自动清理任务。

数据库 schema version 1：

- `payloads`：digest、encoding=`gzip-json-v1`、UTF-8 原始字节数、压缩正文。
- `reads`：scope_key、vehicle_key、state_time、fetched_at、observed_at、source、digest 外键。
- 唯一读取键：scope + vehicle + observed_at + fetched_at + source + digest。
- 压缩只是存储优化，不是加密；内容需要同等隐私保护。

## 安全与故障边界

- 数据目录与年目录权限 700，数据库 600，仅服务用户/管理员可读；拒绝符号链接目录/文件、他人持有或组/其他用户可读的归档。
- 包含车辆位置与身份等完整车况敏感信息，仅服务端保存。不进入 Git、项目文档、静态目录或浏览器完整响应。没有新增下载或原始历史 Web API。
- payload 与 read 在同一 SQLite 事务提交；并发采集/手动刷新通过写锁串行化，gzip 正文和读取关系不半写。
- 先归档成功，再更新最新快照及监控状态；磁盘满、权限或 SQLite 失败向上抛出，不能静默声称采集成功。
- 归档成功后如果最新快照写入失败，已归档的真实读取保留；重试不删除既有证据，不制造事件重发。
- 发布前停服务复制私有数据目录的现有备份流程会包含归档。运行中备份须使用 SQLite backup API 或先停止写入，不能仅复制正在写的数据库文件。
- 旧版本回滚只暂停新增归档，不破坏已有归档；继续保留原 latest snapshot / monitor schema 兼容性。
- 历史分析将来按授权车辆读取白名单字段，明确去重和状态时间口径；不能把读取次数当成新观测次数。

## 验证

`tests/test_snapshot_archive.py` 覆盖完整嵌套响应还原、无损类型、重复读取/内容去重、同时间修正与旧缓存、北京时间跨年、作用域/车辆/来源隔离、只读不写归档、失败不推进最新状态、事务回滚、并发、权限和非法时间。
`tests/test_monitor_runtime.py` 验证实际后台入口包括重复缓存的读取归档，且不引入额外车辆请求。
上线验收仅读取归档行数、大小、权限、时间和完整性摘要，不输出完整实车 JSON。
