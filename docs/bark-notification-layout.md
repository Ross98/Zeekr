# Bark 通知分组与文案

本轮只整理极氪通知的分组和内容，不改变触发阈值、确认规则、推送优先级、接收设备、重试、去重、恢复状态机或企业微信通道。没有发送真实测试通知。

## 分工

| 分组 | 内容 |
|---|---|
| 极氪 · 行程 | 行程开始、结束 |
| 极氪 · 充电 | 充电开始、结束 |
| 极氪 · 车辆提醒 | 胎压、自定义条件提醒及其既有恢复消息 |
| 极氪 · 采集 | 1509 持续重试、自动续期结果需人工核对 |
| 极氪 · 服务 | 极氪任务、网页、采集可用性与巡检失效 |
| 极氪 · 存储 | 极氪所在磁盘的空间异常、恢复 |
| Mac mini Server | 独立 Server Monitor 的整机与服务告警；用户确认保留 |

分组在事件源绑定，不通过中文标题关键词猜测。配置和设备 Key 沿用原文件；未分类的兼容调用保留旧 `Zeekr` 分组。新消息采用新分组，旧通知历史不删除或重发。独立 Server Monitor 的代码、配置和进程均未更改。

## 内容

- 行程结束：结束观测时间、SOC 两端、已观测里程、观测时长。片段明确提示，未知不补零；不能声称已完整记录整段行程。
- 充电结束：SOC 两端、可计算时的充入电量估算、观测时长。SOC × 容量必须标估算，不冒充电表读数。
- 企业微信：提示去查看详细报告及网页投递状态，不声称另一通道已经发送成功。
- 1509：持续重试标题为“极氪采集暂缓”；需人工核对标题为“极氪账号需核对”。保留网关原话、影响与处理提示；只有网关确实说明维护时才展示维护，不能从代码 1509 推断维护。用户要求的私人 Bark 原话策略不改，日志／公开健康状态的隐私边界不改。
- 胎压：轮位、实测压力、参考值、观测时刻，并说明软件参考及云端缓存可能延迟。
- 服务：具体异常／恢复原因、极氪服务来源和处理入口。整机告警属于独立监控，不把整机压力塞回极氪告警。
- 存储：保留 macOS 估算可用与即时空闲两种口径；有完整读数时列极氪目录大小。明确空间属于所在磁盘，不能归因于极氪；提示管理入口与未自动清理。

## 状态保护

本轮不补发历史事件，不改变已有发送签名。不确定投递不重放，Bark 不确定时不触发企业微信兜底。1509 恢复仍沿用撤销待发告警和清除活动状态的既有实现，不新增恢复推送。
