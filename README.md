# Zeekr Control：老款 001 读取与 Web 仪表盘

中国区 Python 命令行原型，兼容本机 Python 3.9.6，零第三方运行依赖。支持副账号短信登录、已有 JWT 导入、车辆列表及缓存状态读取。不包含远程控制。

现已提供响应式 Web 界面：车辆总览、逐项门窗与胎压、能源参数、位置地图、本地轨迹记录与参数搜索。复用已有会话：

新增独立后台 `monitor`：自动记录行程、下电十分钟确认后总结，以及充电开始/停止通知，发送到企业微信群机器人。需要单独启用并配置私有 Webhook，详见 [自动监控说明](docs/monitor-usage.md)。`web` 命令本身仍不自动启动监控。

```bash
python3 -m zeekr_control web
```

打开 <http://127.0.0.1:8765>，点击“刷新状态”。地图需主动开启；周期采集默认关闭，在设置中开始/暂停。云端历史轨迹尚未接入，不会以空列表假装查询成功。完整操作、存储与验证边界见 [Web 使用说明](docs/web-usage.md)。

账号与车型兼容性需在本机验证；缓存状态不等于实时状态。 该结果仅针对本次账号和老款 001，不代表所有车型或今后接口持续可用；缓存状态不等于实时状态。

## 开始

在 Mac 终端执行：

```bash
cd /path/to/Zeekr
python3 -m zeekr_control login
```

输入已接受车辆分享的副账号手机号，回车后发送一次短信；随后输入验证码。两项输入均隐藏。不要把验证码或 Token 发到聊天。新登录可能使同一副账号的官方 App 会话下线。

登录完成后：

```bash
python3 -m zeekr_control vehicles
python3 -m zeekr_control status
```

多辆车时，按列表序号选择：

```bash
python3 -m zeekr_control status --vehicle 1
```

status 默认输出中文摘要：动力电池电量、电池续航、里程、温度和服务端更新时间。缺失或非法数值显示未知；不使用低压电池电量替代动力电池电量。用户已核对本车的已锁车、未充电、四门/尾门/四窗关闭组合；仅匹配这些组合时显示中文状态，缺失或其他状态码仍显示未知和原值。胎压按已核对轮位显示 kPa，保留接口小数。所有状态仍以缓存更新时间为准。

需要核对服务端字段时：

```bash
python3 -m zeekr_control status --json
```

JSON 输出保留服务端结构，不猜测门锁枚举、胎压单位或位置坐标系。默认隐藏常见身份、位置及凭据字段；未知字段仍可能含隐私信息，分享输出前请检查。仅在本机查看完整 VIN、位置时使用 `vehicles --full` 或 `status --json --full`；凭据字段仍隐藏。摘要不显示位置或身份信息。

已有 JWT 时可选择：

```bash
python3 -m zeekr_control login --token
```

此操作仍会换取 GW2 会话，不保证不会影响同账号的其他会话。

## 凭据

会话存于 `~/Library/Application Support/ZeekrControl/session.json`，目录权限 700，文件权限 600。内容是明文 accessToken、userId、clientId、deviceId，不是加密保险箱；不保存手机号、短信验证码、JWT 或刷新 Token。项目目录不保存账号凭据。

```bash
python3 -m zeekr_control logout
```

仅删除本机会话，不撤销云端令牌。

## 故障处理

- `尚未登录`：先运行 login。
- HTTP 401/403、会话失效或被替换：在本机重新登录；程序不自动重试或循环发送短信。
- 签名失败、缺少字段、接口未授权：保留命令名和网关代码即可，不要发送 Token、完整 VIN 或抓包原件。需进一步核对当前国内 App 协议。
- 列表为空：核对副账号是否已接受车辆分享。
- 状态读取采用 `latest=Local`，不会主动唤醒车辆；服务端状态时间才是车辆数据时间。

## 查询并发、缓存与限流

- 默认公共客户端使用本机跨进程请求锁：CLI、Web 刷新、后台采集共用，同一私有目录最多一个网关请求在执行。当前实现对不同账号也串行，是比同账号并发 1 更保守的本机限制。
- 同账号状态请求至少间隔 60 秒，失败请求也计入间隔。不同车辆不绕过这个账号级间隔；无可复用结果时会提示等待，不自动补发。
- 车辆列表与每辆车的状态成功响应缓存 60 秒。相同账号和会话的多个客户端共享缓存，避免每次执行 status 都重复查询列表。重新登录或切换账号不会复用旧会话缓存。
- 本机缓存与极氪云端缓存是两层缓存。CLI 命中本机状态缓存时会提示；Web 的读取时间沿用实际网关读取时间，不因页面复用缓存而更新。
- HTTP 429 按 Retry-After 秒数或 HTTP 日期建立共享冷却；头部缺失或无效时暂停 60 秒。冷却适用于本机各网关及登录请求，已有有效缓存仍可读取。程序不会自动重试。
- 网络超时保持 20 秒；等待并发锁最多约 25 秒，无法取得锁时不绕过保护。
- 私有缓存位于 `~/Library/Application Support/ZeekrControl/queries.sqlite3`，目录权限 700、文件权限 600。缓存包含原始车辆状态（包括位置），是本机明文数据，不是加密存储。过期记录在后续查询时清理；logout 仅删除会话，不负责物理擦除缓存数据库。
- 这些是本项目的保护配置，不是极氪官方公布的并发额度。不能限制其他软件、其他电脑或手工直接调用云端 API。
- Web 服务如已运行，需重启后加载新客户端逻辑。无需重新登录。

## 本地配置与隐私

仓库不包含账号会话、查询缓存、轨迹数据库、实车快照或个人车型资料。首次克隆可选择复制通用资料模板，再填写自己的车辆名称：

```bash
cp zeekr_control/vehicle_profiles.example.json zeekr_control/vehicle_profiles.json
```

本地 `vehicle_profiles.json` 已加入忽略规则；未配置时显示通用车辆名称。测试使用虚构身份、固定测试时间与合成车辆数据。上传前检查见 [隐私检查说明](docs/privacy.md)。
