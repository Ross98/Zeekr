# 01 · 报告内容与样例

目标：收到一条消息，能读到事件结果、起止参数、停车/充电状态、值得留意的变化和数据覆盖情况。详细但有层次。所有样例均为合成数据，不是本车实测结果。

## 1. 通用结构

按以下顺序渲染；不存在的可选块整块省略。

1. 标题 + 核心结果；部分记录直接标在标题。
2. 最多三条需要留意的状态；未知不当故障。
3. 地点、时间或区间。
4. 电量、续航及事件统计。
5. 结束状态或停车后最新有效状态，带观测时间。
6. 温度、四轮胎压胎温及起止变化。
7. 充电过程或历史对比。
8. 覆盖情况、估算说明、缓存时间/延迟说明、12 位事件编号。

用户文案用普通中文；不要把内部路径、quality 枚举、协议码塞到群消息里。

## 2. 行程结束

### 2.1 字段顺序

| 区块 | 必备/优先内容 | 条件内容 |
|---|---|---|
| 结果 | 距离、观测时长、完整性 | 标题部分记录 |
| 行程 | 出发/到达地址、起止时间 | 起点可能遗漏 |
| 能源 | 起止 SOC 与百分点差；起止云端续航与差值 | 容量估算耗电、百公里估算、额定续航达成率 |
| 行驶 | 全程平均速度、采样最高速度 | 都有独立有效性条件 |
| 停车 | 状态时间、动力、锁车、四门、四窗、尾门 | 前舱盖、交流/直流口盖 |
| 环境 | 车内外温度；四轮胎压、胎温 | 起止变化，独立温度时间 |
| 对比 | 本车相近行程、样本数、比较口径 | 数据不足时省略整个对比块 |
| 质量 | 独立观测数、最大间隔、缺口/延迟 | 参数省略说明 |

车门和车窗全四项确认关闭才合并。部分未知时举例：`车窗：3 扇确认关闭，右后未确认`。四轮永远固定顺序左前、右前、左后、右后，不把缺失值挤掉导致位置错位。

### 2.2 具备当前证据的详细样例

```text
🚗 行程结束｜23.6 公里 · 42 分钟

某某小区附近 → 某某广场附近
09月19日 09:18—10:00

【电量与续航】
电量：78% → 72%（下降 6 个百分点）
云端续航：420 → 386 公里（减少 34 公里）
估算耗电：约 5.2 kWh
估算百公里耗电：约 21.9 kWh/100km
平均速度：33.7 km/h（含途中停车）
采样最高速度：76 km/h

【停车后状态 · 10:08】
动力已下电 · 已确认锁车
四门关闭 · 四窗关闭 · 尾门关闭
交流口盖关闭 · 直流口盖关闭

【温度与轮胎】
车内：38 → 25℃；车外：26 → 25℃
温度时间：09:18 → 10:00
结束胎压 kPa：左前260 / 右前260 / 左后270 / 右后270
结束胎温 ℃：左前32 / 右前32 / 左后33 / 右后33

独立观测43次，最大间隔60秒。
耗电按86 kWh容量估算；最高速度仅为采样值。
状态来自云端缓存；行程于10:00结束，停车状态另取10:08观测。
编号：a1b2c3d4e5f6
```

示例容量仅用于展示公式一致性。真实实现从事件冻结配置读取，不能把 `86` 硬编码。数值先按未取整原值计算，再显示：86×0.06=5.16，5.16÷23.6×100≈21.9。

### 2.3 起点缺失或期间断档

标题：`行程结束｜部分记录`。时间改为“已记录区间”，平均速度改为“记录区间平均速度”。可显示可靠的起止里程差，但写“已记录里程”；SOC 耗电只描述相应端点区间。百公里耗电、达成率和历史比较不出。

有两个有效端点但中间缺样时，“最大观测间隔 8 分钟”不等于“这 8 分钟未行驶”。保留总里程端点差与端点 SOC 差，不补造速度、路线或暂停时长。完整性行说明具体原因。

## 3. 充电开始

当前确认直流时写“直流充电”；仅确认 charging=true 而模式未知时写“充电”。不要把所有直流称作某功率等级“超充”。

```text
⚡ 检测到开始充电｜直流

地点：某某停车场附近
首次检测：09月19日 18:05

电量：32% · 云端续航：168 公里
桩侧观测电压：400 V
桩侧观测电流：150 A
按电压×电流计算功率：60.0 kW
截至18:05，车辆估计剩余45分钟
按本次估计约18:50结束，估计可能变化。

【车辆状态 · 18:05】
动力已下电 · 已确认锁车
四门关闭 · 四窗关闭 · 尾门关闭
直流口盖打开 · 交流口盖关闭
充电枪连接：未确认

车内27℃ / 车外25℃（温度观测18:04）
目标电量：暂未取得
云端观测；真实开始时间可能更早。
编号：b1c2d3e4f5a6
```

电流、电压必须同一观测、同为桩侧，只有有效充电证据才计算功率。预计结束按车辆状态时间加剩余分钟，不按发送时间加；首次冻结正文时观测已超过180秒，或估计结束时间已过去，则省略预计结束。剩余分钟始终保留“截至观测时间”的含义，细则见03 §6.4。

首次接入已在充电：标题改为“车辆正在充电｜中途开始记录”。写“实际开始时间、实际起始电量未知；下列为首次观测值”。不得等待后续样本以丰满开始报告，也不新增补发。

胎压胎温若有效可追加统一四轮格式。目标电量、动力电池温度仅在能力门控通过后插入能源区块。

## 4. 充电停止

```text
🔋 充电已停止｜电量80%

地点：某某停车场附近
09月19日 18:05—18:51
观测区间46分钟，实际停充时刻可能更早。

【补电结果】
电量：32% → 80%（增加48个百分点）
云端续航：168 → 426公里（增加258公里）
估算充入：约41.3 kWh

【充电过程】
类型：直流
最高采样功率：96.0 kW
观测区间平均功率：56.0 kW
功率有效覆盖：40/46分钟（87%）
后段较前段观测功率下降约24%

【停止观测 · 18:51】
桩侧电压410 V · 电流0 A
目标电量：暂未取得
停止原因：未确认
充电枪连接：未确认 · 直流口盖打开
动力已下电 · 已确认锁车
四门关闭 · 四窗关闭 · 尾门关闭

独立观测47次；功率缺样区间未补算。
充入量由容量与SOC估算，不等于桩计费电量。
状态来自云端缓存，可能延迟。
编号：c1d2e3f4a5b6
```

功率例子和 SOC 容量估算是不同统计，不要求二者相等，不推算“充电损耗”。只有 03 的功率条件满足才显示相应行。可用的温度、胎压及历史对比按预算插入。

停止事件本身不改名“充满”。目标证据充分时增加“停止观测电量已达到当时设定目标”，仍不据此认定停止原因。满 100% 也只说明观测 SOC 为 100%。

中途接入示例核心文案：

```text
🔋 充电已停止｜部分记录
已记录电量：56% → 80%（增加24个百分点）
已记录区间：18:25—18:51，共26分钟
该区间估算充入：约20.6 kWh
监控中途开始记录；以上不是整次充电统计。
实际开始时间和起始电量未知。
```

## 5. 空值、变化、时间及单位

| 情况 | 规则 |
|---|---|
| 核心字段缺失 | 时间、SOC、距离、停车安全状态用“未知/未确认”，不假装正常 |
| 未支持候选参数 | 连接、目标、停止原因在对应充电报告保留简短未知；电池温度/舒适配置等无数据整行省略 |
| 其他可选指标无可靠数据 | 省略；质量行可写“能耗估算条件不足”或“功率覆盖不足” |
| 未核验状态码 | 显示未确认；原码只在私有诊断，不进群 |
| 不适用配置 | 不渲染；不显示“故障”或“关闭” |
| 行程 SOC 上涨 | 如实写上涨；不输出负耗电、负能耗或负达成率 |
| 续航上涨/下降 | 如实写；续航来自云端估计，不等于实际可再行驶距离 |
| 四轮单位 | 默认 kPa；如将来切 bar，用100 kPa=1 bar转换，不混用同一行单位 |
| 小数 | SOC至多1位，距离1位，温度/胎压至多1位，功率与kWh1位；不通过显示取整反算指标 |
| 同日 | 月日写一次，时间范围 HH:mm—HH:mm；跨日写两端日期，跨年写年份 |
| 时间语义 | 所有显示用北京时间；起止观测、停车状态、温度时间分开 |
| 地点 | “某地附近”；地址无法获取写“位置未知”；不写精确坐标 |

文字字段先去控制字符、换行和多余空白，防止伪造报告行。不得盲目把地图返回的完整地址判断为准确充电站名或“家/公司”。沿用地址上限时用省略号标识截断。

## 6. 2048 字节预算和裁剪

默认纯文本单条发送。内部目标不超过1900 UTF-8字节；发送硬上限2048字节。最终文本用 UTF-8 编码实测，不按中文字数/字符数猜。1900仅是设计余量。

渲染先保留完整语义块，再依序减项至满足目标：

1. 删除重复解释和可有可无的装饰；用一行合并共同时间、单位。
2. 去掉历史比较的第二项、详细规则说明；再移除整块历史比较。
3. 省略额定续航达成率、前后段功率细节、逐轮起止变化；保留结束四轮数值。
4. 压缩温度/轮胎块；优先保留有状态提示关联的项目。
5. 地址分别限制为24个Unicode字符并加省略号，仍显示出发/到达角色；必要时退成“位置已记录”。
6. 最后退到核心模板：标题、严重/注意状态、起止时间、距离/时长、SOC、关键门窗锁/充电状态的未知、部分/陈旧说明、估算标记、12位编号。

任何裁剪不得删除估算性质、部分记录标记、状态时间、未知/陈旧提示，或只截掉句子的“不”。保留“部分参数因消息长度省略”并计入预算。最多三条置顶提示，其余归纳为“另有N项需留意”，详细值留私有报告；不能归纳成“一切正常”。

最小核心模板应在上限内（测试含最长标题、跨年时间、三条提示、emoji、双长地址）。若仍超限，返回本地渲染失败并留完整私有数据；不调用发送器、不拆多条、不截原始字节造成乱码。事件重试/人工处理按05，不借长度故障扩大重发范围。

## 7. 消息之外的数据

完整参数、来源、区间质量、比较样本ID及裁剪原因保存进私有报告对象。当前项目没有普通手机可直达的安全报告页；本轮不新增报告URL，不在消息里承诺“点此查看”。后续可用本地离线预览检查完整版和发送版，预览不触发采集或通知。
