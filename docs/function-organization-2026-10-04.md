# 现有功能分类与入口整理 · 2026-10-04

本轮整理全站导航和页内任务入口。已有功能、工具 ID、接口、记录与计算口径保留。本文记录实现与本地验收；提交、线上版本及回滚信息以发布记录为准。

## 分类

桌面侧栏与手机“更多”共用一份分类定义，避免两端入口归属漂移。手机底栏仍保留总览、车辆、轨迹、更多。

| 一级分类 | 页面 | 页内任务 |
| --- | --- | --- |
| 日常用车 | 总览 | 车况、缓存位置、当日记录、待处理事项 |
| 日常用车 | 行程与轨迹 | 本地记录、云端历史、行程标签、常走路线对比 |
| 日常用车 | 能源与充电 | 充电状态、充电记录、充电账本、充电曲线对比 |
| 日常用车 | 车辆 | 车辆状态、生活账本 |
| 回顾与研究 | 用车日历 | 按日查看行程、充电、停车与补录入口 |
| 回顾与研究 | 用车周报 | 周报与月报 |
| 回顾与研究 | 用车研究 | 数据分析、历史回看、参数核实 |
| 采集与设置 | 设置 | 采集与设置、自定义提醒、数据质量雷达 |

研究工具分三组，每组两项：

- 数据分析：数据利用、自动洞察。
- 历史回看：车辆时间机、轻量用车回顾。
- 参数核实：参数字典、参数实验室。

日历、周报保留一级直达；位置继续嵌在总览，可手动隐藏。费用事实、耗能估算、缺失与零值的区分保留。

## 行程操作修整

行程四个任务统一放在一条页内导航，桌面和手机均可使用。删去标签重复入口；选中态明确；从路线对比可直接返回本地、云端或标签。进入标签保留页面顶部导航，避免自动滚动后失去切换入口。

新增回归测试发现：路线对比独立显示时，旧代码仍按之前的行程来源挂载列表，触发空节点 `scrollTop` 错误。已按当前任务约束行程列表、标签、地图、管理器、后台重绘和导航恢复；未显示的行程任务不再挂载。路线对比刷新后仍保持选中。

## 后续修复（用户要求“先修吧”）

上一轮留存的三项问题已修：

1. 手机总览顶部状态、提示与温度区域过高。保留车型、锁车/充电、门窗、缓存时间、温度和恢复动作，缩小非交互区域的间距；常用动作仍不小于 44px。390×844 合成样例中电量/续航卡底部由约 923.84px 降至 767.05px，位于底栏上沿约 778.20px 之上。今日里程和月度费用仍在下一行；320px 允许自然折行，没有横向溢出，不承诺所有尺寸/异常长文案都塞进首屏。
2. 首屏检查原来测量整块四卡容器，却声称检查电量与续航。已改为直接检查这两张卡，边界使用底栏上沿，防止内容被固定导航遮住。新增 `ui_overview_layout.cjs` 同时验证日夜主题、缓存/未知温度说明、44px 动作保留、长恢复信息折行以及旧文字区域对比度。
3. 日期测试已改用独立“用车日历”“用车周报”入口；行程测试先显式隐藏默认展示的位置，再测试 consent 流程，底图桩切换高德。保留这些文件原有其他未提交改动。
