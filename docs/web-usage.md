# Zeekr Web 使用说明

## 启动

在项目目录运行：

```bash
python3 -m zeekr_control web
```

打开 <http://127.0.0.1:8765>。指定其他端口可运行 `python3 -m zeekr_control web --port 8766`。服务只监听本机，其他设备不能直接访问该本机地址。本轮优化和验收仅覆盖桌面端。终端按 Ctrl+C 停止服务；重启后统一采集默认开启。

Web 复用已有会话。若未登录，在另一终端运行 `python3 -m zeekr_control login`，完成后返回页面点击“刷新状态”。刷新只读取云端缓存，不主动唤醒车辆。

## 页面

以下子功能归属仅适用于桌面网页；手机端菜单未调整。

- 总览：突出动力电池电量与预估续航，累计里程作为次要信息。锁车状态旁展示缓存年龄和门窗摘要；温度使用独立更新时间。胎压总览四舍五入到一位小数，车辆详情保留接口精度。
- 车辆：每个车门、门锁和车窗分别展示；完整参数目录可搜索和筛选；生活账本位于“用车账本”，原始归档位于参数研究的高级取证。
- 能源与充电：默认月度充电回顾；充电记录保留单次曲线和管理，能源参数单独展示。充电账本仍从用车账本进入。停车观测保留后台采集和分析，通过行程与用车日历查看。
- 参数研究与核实：位于“用车研究”，默认优先展示有有效值的待研究参数；已确认、不适用和本次未返回参数可通过“全部参数”查看。点击“分析近 7 天”按需分析本地归档，筛出有变化的待研究参数，显示变化次数、前后原值及观测时间区间。新入口的总览和字段读取共用串行请求，快速切换只保留最后一项待读取参数；离页清空排队请求，已开始的同步扫描仍允许完成。选中参数后直接看变化、写结论；术语来源和补充记录默认折叠。高级研究保留假设与反例、操作实验、完整历史、分布、场景和原始归档取证。切换视图保留草稿，人工核实独立保存，不修改运行解码或通知。
- 地图：主动点击“显示位置并加载地图”，才请求定位数据和外部底图。
- 行程与轨迹：默认按北京时间显示当前车辆的已结束行程摘要；子功能为行程标签和行程卡片。地图和路线仍需主动显示。
- 用车研究：仅保留参数研究与核实，不再提供数据利用、自动洞察、车辆时间机、轻量用车回顾的独立工具入口。数据分析与原始归档作为研究取证能力保留。周报增加按需读取的本周参考地点和折叠的近期能耗趋势；趋势采用独立的最近 7 天与此前 21 天窗口，按原分析时间显示。费用和待补账单统一在费用总览查看。
- 设置：开始/暂停采集、自适应采样状态、位置隐私、本地存储和自定义提醒。

页面每 5 秒读取本地最新快照和服务状态，这个检查不访问车辆网关。后台采集成功后，下一次轮询自动显示新车况。服务重启后可恢复相同会话和车辆的私有最新快照；没有匹配快照时保持空态。手动刷新失败时保留旧数据和原时间，不将失败或未知值替换成 0。

最新快照保存在运行服务设备的私有 `snapshots.sqlite3`。按会话摘要和车辆摘要隔离；带有效车辆时间的快照不会被更早或无时间数据覆盖，同一车辆时间的内容修订会增加快照 revision。状态查询缓存使用所选采样间隔；共享查询锁和 429 冷却不变。

## 总览的刷新与连接提示

手动刷新区分“复用本机缓存”“读取云端但车辆数据未更新”“获得新车辆数据”。时间缺失时单独提示未知，时间倒退不会声明获得新数据。“新”仅指与上一次读取相比的车辆时间变化，不代表实时状态。

后端返回可再次请求的时间，刷新按钮显示倒计时；倒计时结束不会自动查询云端。同账号状态查询保护跟随所选采样间隔，跨进程锁和 429 冷却规则保持不变，其他客户端并发操作仍由后端保护。

状态时间以服务端时间戳计算相对年龄，每秒本地更新；“数据说明与完整时间”可展开查看北京时间、字段依据与胎压精度。没有时间或时钟明显超前时明确提示，不猜测更新年龄。

本机轮询连续两次失败后显示断连提示并保留页面旧值。恢复后自动消除提示，也可以点击“重新连接”；该按钮只检查本机服务，不读取云端车辆。初次连接失败同样提供重连入口。

行程卡显示后台未在线、已暂停、正在记录或采集失败。最近观测时间读取后台共享状态；服务重启默认恢复采集。

## 车辆显示资料

将 `zeekr_control/vehicle_profiles.example.json` 复制为被 Git 忽略的 `zeekr_control/vehicle_profiles.json`，在本机填写名称、年款配置及参考图片。`single_vehicle` 是当前用户单车场景的本地展示资料，只在账号恰好返回一辆车时使用，不属于云端车型识别结果。换成另一辆单车时应同步修改该资料。

多车场景在 `vehicles` 中按 VIN 的 SHA-256 摘要配置，优先于单车资料；未配置车辆显示“车辆 N”，不套用极氪 001 图片。摘要可在本机根据 VIN 计算，不需要将 VIN 发给外部服务。图片仅允许当前本地资源 `/car.svg` 或空值，资料文件不存放凭据。修改后下次成功读取车辆时生效。

## 定位

使用本地打包的 Leaflet 1.9.4，底图来自 OpenStreetMap 标准瓦片服务，保留地图署名并遵循其使用政策；没有离线预取或批量瓦片下载。底图是否可用取决于本机网络。

按已观察到的 GW2 整数经纬度格式除以 3,600,000；兼容 JSON 布尔值和字符串 `"true"` / `"false"`。`marsCoordinates=false` 暂按社区解释视为 WGS84，在底图展示前仍需用户核验对齐。GCJ-02 或坐标系未知时不在 WGS84 底图强行落点；未验证格式、非法值不绘制。

定位可信标记为 false 或缺失时，用灰色候选点表示“位置未确认”。没有 GPS 采集时间时明确显示未提供，不将整车更新时间当成 GPS 时间。位置文本默认隐藏；用户可进一步点击“显示经纬度”。

外部底图服务收到相应区域瓦片请求；Token、VIN 和完整车辆响应不会发送给底图供应商。隐藏位置会移除当前地图，但不删除记录、不停止已开启采集。

## 本地轨迹

网页与后台监控共用一个采集任务、车辆绑定及轨迹数据库。Web 服务启动默认开启；已有独立监控时通过进程锁复用，没有时由 Web 承担同一后台逻辑。无需先打开网页或手动刷新。

默认 30 秒；在“正常采样间隔（秒）”输入 10–60 秒整数并保存。保存间隔不会开始或暂停采集；暂停／恢复及服务重启保留已保存的间隔。停车、充电、行驶均保持所选间隔；更快查询不保证车辆上传更快，重复数据不会新增轨迹点。设置页区分已保存间隔和后台最近等待间隔；故障或 429 冷却可能使实际等待更长。轨迹超过 180 秒仍分段，不把缺失路段连起来。

设置中的暂停同时停止自动车辆检查、轨迹记录和通知处理，开始后继续。关闭浏览器不停止后台；Mac 休眠、断网或所有服务停止期间无法采集。网络错误退避重试，账号失效需更新会话。Web 或监控服务重启默认重新启用。手动刷新页面不额外写入轨迹，也不改变后台已绑定车辆；多车首次绑定按 [监控说明](monitor-usage.md)明确选择。

相同缓存只保存一次；相同坐标但服务端时间更新时保留观测。无 GPS 时间不生成伪造 GPS 时间。只连接可信且时间连续的点，超过 180 秒、时间倒退或遇到不可信观测时分段。路线是采样折线，不是道路导航路线；不补回未采集的历史路段。

轨迹页固定当前车辆，按北京时间日期筛选。默认“全天总览”，也可点击某趟行程，仅查看该趟的时间、里程、电量及路线；跨午夜行程按结束日期归档，单趟路线查询包含完整起止时间范围。进行中的记录会区分“行程记录中”和“停车确认中”；均来自后台缓存观测，不代表实时状态。

摘要只返回起止时间、时长、里程、SOC 变化、记录状态和事件保存的电池容量，不含地址、坐标或通知正文。选择行程不会自动请求路线；点击“显示位置并加载地图”才读取位置和底图。首末标记代表实际记录中的可绘采样点，不冒充未采集的真实出发、到达位置。采样缺口显示时间和已知原因，在可确定的地图边界处标记，不跨缺口补线。行程完整性与路线采样情况分别说明。

路线观测优先使用缓存状态时间，缺失时采用本机观测时间；每次最多显示 5000 条，截断时明确提示。滑块、上一点／下一点和播放／暂停均可回看，1× 每秒前进一个采样点，可选 2×／4×，并非实际车速。后台轮询保留所选行程、地图视角与回看位置；切换日期、行程、来源，离开页面或隐藏位置会停止播放。采样详情可展开查看。

服务重启且暂时无法刷新云端时，优先沿用后台绑定车辆；无绑定但仅有一辆本地车辆时仍可回看。存在多辆归档且无法确认当前车辆时明确拒绝任选，轨迹页不提供车辆选择器。联网底图不可用时仍可查看本地记录及采样详情。

“行程与轨迹 → 行程标签”按月列出已结束行程；该视图使用独立月份，不随本地记录的日期切换。列表并列显示起止时间、里程和时长；选中后可点“查看路线小地图”按需读取该趟本地采样并加载底图。默认不读取位置；无可绘采样时保留行程摘要并说明无法绘制。首末标记是采样点，不代表真实出发地或目的地。标注时可点选当前车辆曾用标签，也可输入新标签并添加备注；保存后保留当前行程供核对。“筛选标签”可选“未标注”，即标签列表为空的行程；可与完整性筛选叠加。

“通勤自动标注”可在地图上点选家和公司，拖动标记调整中心，并分别设置 100–1000 米圆形范围（默认各 300 米）；两个圆不能重叠。通勤设置独立读取，无需先读取标签月份。规则保存后，只对结束时间晚于保存时间的新行程生效；采集后台对最近 48 小时内、最多 100 条已结束行程自动判定，读取标签月份也可补充判定。使用起止各 180 秒内的可信 WGS84 位置采样，两个方向均可匹配；页面显示方向、端点距离及范围。缺少可信证据或超出范围时，采样变化后可以重试；没有变化不重复写入。观测片段可以标注位置匹配，但会提示不能确认完整通勤。可暂停、恢复、删除规则；已命中的旧判定保留。

需要补标历史或修正旧判定时，在选定月份先“预览本月历史重判”，核对新增、移除、手动排除和证据不足，再应用已保存的当前规则。规则、行程、采样或排除状态变化后须重新预览，每月最多重判 1000 条行程。重判只修改自动标签，手工标签、备注及手动排除均保留；取消单趟自动标注后，不会自动补回。

## 历史记录来源

行程、停车观测和轨迹均从本机归档读取。厂商云端历史查询及专用授权导入已移除；旧云端历史链接回到本地记录，并保留所选日期。已有行程、归档、查询缓存和其他配置保留，不会自动补画未采集的路线。

## 验证

```bash
python3 -m unittest discover -s tests -v
node --check zeekr_control/static/app.js
```

`tests/ui_overview.cjs` 覆盖桌面 1440、1280、1024 像素布局、时间、门窗、精度、刷新分支、倒计时与断连恢复，截图在 `/tmp/zeekr-overview-qa/`。

运行 `DESKTOP_ONLY=1 node tests/ui_smoke.cjs` 可仅回归桌面其他页面。

`tests/ui_smoke.cjs` 使用 Playwright 和 `tests/web_fixture.py` 的合成响应验收浏览器，不读取真实会话。需要本机可用的 Playwright 与 Chromium；可通过 `NODE_PATH` 和 `CHROMIUM_EXECUTABLE` 指定安装位置。截图在 `/tmp/zeekr-web-qa/`，属于合成数据界面验收，不是车辆状态证据。

运行期 Python 不需要额外第三方包；Node/Playwright 仅用于开发验收。界面不包含远程车控或通知系统。


## 能源与充电：标称续航与实际行程达成率

能源页默认“充电回顾”，按北京时间的充电结束月份统计。主数字依次为已知费用、SOC 估算累计补能、充电次数，费用缺失不按零计算。费用按历史 AC／DC 分组，无法确认的单列未知。综合电价只使用费用与电表电量均有记录的同一批账单。当月比较上月相同已过时段，历史完整月份比较整月；百公里成本仅纳入历史补能成本可匹配的有效行程。

月内记录以时间轴倒序展示历史地点、起止时间、时长、电量条与费用；展开查看实际电表电量、完整性、补账和单次曲线。SOC 与电表电量口径分开，片段不补算缺失；历史地点无依据时保持未知。回顾只读本地已保存记录，不请求车辆，也不展开原始快照归档。“充电记录”保留日期区间查询、分页、记录详情和按需管理。“能源参数”保留原始字段和低压电池。后台刷新保留标签和阅读位置；重载保留回顾月份。旧当前状态、充电统计及曲线对比书签转入回顾。

在本地 `zeekr_control/vehicle_profiles.json` 的对应车辆资料中配置 `range_km`、`range_standard` 和 `range_source`。标称里程必须是大于 0 且不超过 3000 的有限数值，标准支持 CLTC、WLTP、NEDC、EPA。示例模板不预设车型续航；多车场景通过 `vehicles` 分别配置，未配置的车辆不继承其他车型数值。

2023 款极氪 001 WE86 四驱参考值为 546 km（CLTC）。本次核对依据为[爱卡车型配置表](https://newcar.xcar.com.cn/m68120/config.htm)和[2023 款上市报道](https://www.ithome.com/0/664/912.htm)，属于第三方资料，并非已取得的旧款官方配置原页。

计算方式：实际行驶里程 ÷（标称续航 × 消耗电量百分点 ÷ 100）× 100%。例如行驶 80 km、电量从 80% 降至 60%、标称 546 km，对应标称里程为 109.2 km，结果为 73.3%。里程来自行程起止总里程之差，耗电来自同一行程起止电量之差，不使用当前剩余续航；当前快照变化不会改变历史行程结果。

通过只读数据库查询按当前车辆筛选最近一次 `trip_end`。后台下电确认 10 分钟后生成行程；无记录显示“暂无可计算行程”，不完整、跨充电、耗电为零或电量回升、时间和里程无效、标称值缺失时不计算，不回退使用更早的行程。结果可以超过 100%。起止时间、实际里程与耗电量一并展示；电量取整和云端缓存延迟会影响精度，特别是短行程。该指标不代表电池健康。

修改后端代码后重启 Web 服务，再读取状态；修改车型资料后在下一次成功刷新时加载。仅刷新浏览器不会主动请求车辆云端状态。`tests/ui_energy.cjs` 覆盖行程口径、当前快照独立性、缺失或无效行程、未知充电状态、键盘展开与刷新保留；`tests/ui_energy_workspace.cjs` 覆盖当前与历史隔离、晚到响应、按需查询、标签重载与桌面日夜布局。测试使用合成数据，桌面覆盖 1024、1280、1440 px。

## 外观与夜间阅读

顶栏和登录页的“外观”可选跟随系统、日间、夜间；默认跟随系统。偏好仅保存在本机浏览器，多标签同步，不修改车辆设置。切换时保留搜索、详情选择和输入内容；浏览器禁止本地存储时仍可在当前页面切换。

夜间提高正文、单位、时间和状态说明的对比度，手机窄屏重新排布。充电过程图显示纵轴数值和北京时间；缺失采样保留断线，独立采样点仍显示。地图底图保留原配色，控件随主题切换。
