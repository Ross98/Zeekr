# 数据接口统一约定

本轮按车辆归属、修改联动、业务口径、传输契约顺序落地。保留既有返回字段，不增加 `data` 外层，不迁移或清理个人数据。

## 车辆归属与一致性

行程、轨迹、事件、充电与历史分析使用当前凭据确认的车辆上下文。磁盘上的单车历史或旧 monitor-binding 不能证明新账号拥有该车辆。离线读取仍可使用同一账号的有效本地快照，不需要请求云端；没有已确认的当前车辆时返回 `context_unavailable`。读取中账号、车辆或记录改变，丢弃旧结果，返回 `data_changed`。

`/api/state.personal_records_revision` 是按集合命名的版本字典。账单、日常支出、地点及修正的变化使依赖页面失效；自己的写入响应携带同样的版本，其他窗口通过正常状态轮询发现变化。页面保留筛选与未保存草稿；不自动重放写请求。

## 业务口径

- 时间戳统一用 Unix 毫秒，时长秒；北京时间日期，区间 `[start,end)`。旧 `next_query_at` 秒字段保留兼容，不改变既有调用方单位。
- 结束行程按结束日期归期。跨日行程完整里程只归结束日，不按时间拆分；日历 `overlap_trip_count` 表示当日涉及次数，`ended_trip_count` 表示结束次数。旧 `trip_count` 含义按原接口保留。
- 已结束记录和进行中观测分别展示。未知为 `null`，真实零为 `0`；片段、缺口和估算来源保留。
- 实付为整数分，按账单日期且不晚于查询当天归期。周报充电实付、日历充电实付与费用总览 `charge_cents` 必须一致；费用总览总额另含停车费及日常支出，不能直接与充电实付比较。
- 未来账单、支出保留可编辑，暂不计入实付、图表和费用明细；通过 `future_bill_count` 或 `future_record_count` 说明。充电账本保留未来条目以便编辑。
- 交流／直流依据事件起止的所有已知模式共同判断，冲突或无有效依据为 `unknown`。人工覆盖仅用于明确支持该功能的账本／复盘层，不篡改采样事实。

## HTTP 与元信息

所有 `/api/` JSON 对象增加 `meta`：`schema_version`、`generated_at`、`timezone`、`units`。已有账号上下文、版本字段按原名复制到 `meta.context`／`meta.revisions`。受保护的历史读取另携带 `source=local_records`、查询起点 `as_of` 和不含原始身份的 `data_revision` 摘要。

`generated_at` 只是响应生成时刻；`as_of` 是统计截止时刻；车辆状态时间、最后真实请求时间、本机缓存命中各保留自己的字段。没有证据不补“新鲜”“完整”或统一截止时间。元信息中的单位约定适用于标准数值字段；明确带 `_yuan` 等单位的兼容字段仍按名称解释。

错误统一保留人读的 `error`，增加机器读的 `code`、`retryable`，有可靠等待时间时返回 `retry_after_seconds` 和 HTTP `Retry-After`。前端 Error 对象保留这些信息，不据此自动重放修改。

| 状态 | 语义 |
|---|---|
| 400 | 参数无效／缺少车辆上下文 |
| 401／403 | 网页登录／同源与请求校验 |
| 409 | 记录版本或读取上下文改变 |
| 429 | 本地分析忙，或网关明确限流；用 code 区分 |
| 502 | 网关失败；不是凭据永久失效的断言 |
| 503 | 本地容量、配置锁或依赖暂不可用 |

同步与异步分析共享错误分类。元信息、错误对象不带 Token、原始网关响应或私人通知原因。
