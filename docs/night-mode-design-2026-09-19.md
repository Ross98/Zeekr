# 夜间模式设计：以信息可读性为先

日期：2026-09-19。基线：685103e。范围：设计说明与独立交互预览；未修改业务页面、未提交、未部署。

预览：`previews/night-mode.html`。总览截图：`previews/night-mode-overview.png`。所有数值、时间、字段名均为模拟展示，不连接车辆或外部服务。

## 1. 现状与设计目标

现有页面只有日间样式，`index.html` 固定声明 light。`app.css` 存在大量硬编码白底和灰绿文字；不少单位、时间、说明、原始字段只有 9–11px。充电 SVG 已有断线逻辑，但当前图形没有可见坐标刻度。登录页和存储管理另有独立样式，不能只改根变量。

目标：夜间一眼读出关键值，同时读得清单位、时间、数据来源、未知原因。保留原有信息架构与只读边界，不通过主题改变车辆状态解释。

## 2. 视觉方案

低亮度深灰蓝背景，卡片逐层提亮；正文用柔和近白色，避免纯黑与纯白的大面积强反差。主强调沿用绿色方向，只用于选中项、主要操作、关键图形。数据数字主要用正文色，不把所有数字染绿。

| 语义 token | 夜间值 | 用途 |
| --- | --- | --- |
| background | #11191D | 页面底色 |
| surface | #1A252B | 卡片、顶栏、侧栏 |
| surface-raised | #233138 | 内嵌信息、输入区、悬浮信息 |
| text-primary | #E3ECEF | 主值、正文、标题 |
| text-secondary | #B8C8CE | 标签、单位、解释 |
| text-muted | #9BAFB8 | 时间、来源、补充说明 |
| border-subtle | #40545D | 非交互分隔线 |
| border-control | #718991 | 输入框、未选按钮边界 |
| accent | #80D4BD | 主要操作、曲线、选中状态 |
| on-accent | #10271F | 强调底色上的文字 |
| success / surface | #8BD6B0 / #203B31 | 已核验、最近观测正常 |
| warning / surface | #F0C67D / #3B3020 | 缓存过期、未知、部分记录 |

预览日间配色为对照方案，不覆盖当前生产日间样式。实施时需单独核查日间回归。

## 3. 可读性硬约束

- 正文、表格、字段标签 14–16px；次要时间和说明至少 13px；原始字段路径最低 12px，仅用于非关键技术信息。主要数值 32–40px，单位 15–16px。关键状态禁止 9–11px。
- 行高 1.6；长说明自然换行；中文使用系统字体。表格数据用等宽数字，单位与数值尽量不分离。不靠变细字重区分信息层级。
- 普通文字对比度至少 4.5:1，关键正文目标 7:1；关键图形、输入控件边界和焦点目标至少 3:1。逐个检查实际背景与叠加后颜色，不能只测根变量。
- 不对整张卡片或整行数据设低 opacity。禁用按钮可降低填充强调，但标签仍可读，并给出禁用原因。未知、过期、缺失不等于禁用。
- 状态必须带文字及符号，例如“? 未知”“△ 部分记录”“! 读取失败”；颜色只作辅助。“—”必须配“未提供／尚未读取”等解释，不替换为 0。
- 顶层导航和表单触控区域至少 44px。选中状态有明确底色和可访问状态，焦点外描边 3px。避免仅 hover 才能看到关键说明。
- 320px 手机端改为单列或重新排布，不通过缩小字体塞三列。200% 浏览器缩放需要单独验收；加大文字预览不等同于缩放验收。

已计算的夜间不透明色对比度：

| 色对 | 比值 |
| --- | ---: |
| 主文字 / 卡片 | 13.03:1 |
| 次要文字 / 卡片 | 9.07:1 |
| 最淡文字 / 抬高背景 | 5.88:1 |
| 强调曲线 / 抬高背景 | 7.70:1 |
| 成功文字 / 成功底色 | 7.13:1 |
| 警告文字 / 警告底色 | 8.03:1 |
| 错误文字 / 错误底色 | 7.42:1 |
| 强调按钮文字 / 强调背景 | 9.06:1 |

分隔线只有约 1.97:1，因此仅用于结构装饰；交互控件必须使用更亮的 border-control，不能复用装饰线。

## 4. 页面覆盖

| 页面 | 夜间处理与信息重点 |
| --- | --- |
| 总览 | SOC、估计续航、温度保持大字；每项保留观测时间。过期提示紧邻主要值，车辆图不滤镜反色。图片保留原色，检查透明边缘与深色底的过渡。 |
| 车辆 | 门窗与座舱按项标注已核验／未知。胎压显示单位与轮位；不能因绿色主题额外推断安全。 |
| 能源与充电 | 电气参数、列表、详情、分页、趋势统一表面色。部分记录明确显示；不补算缺失能量。原有完整/部分记录和容量依据保持不变。 |
| 定位与轨迹 | 地图外框、缩放按钮、弹层、归属说明统一主题；地名与道路保持辨识度。保持现有主动加载外部地图的行为。 |
| 参数字典与复核 | 表头、值、原始路径和审核状态分层；搜索匹配采用深底＋亮字，不以黄色亮块刺眼。未知原因与审核备注不淡化。 |
| 设置与存储 | 表单、进度条、确认区、危险操作、失败反馈都覆盖。危险操作使用红色文字＋明确标题，避免整页红底。 |
| 登录 | 页面、密码框、焦点、密码自动填充、错误提示、提交等待全部覆盖，进入仪表盘保持相同主题。 |
| 全局状态 | 加载、空、连接失败、重试、缓存过期、toast、移动导航和跳到主要内容链接都检查；toast 不遮挡主要操作。 |

地图方案：首版保留已验证瓦片原色，不对瓦片整体 invert 或过度压暗。若暂缺支持夜间样式且许可明确的瓦片源，在地图旁显示“地图底图保持原配色”，作为已知亮度例外。后续替换源必须单独确认许可、归属、请求隐私边界和地名可读性；本次不新增外部地图请求。

## 5. 图表规范

功率、SOC、电压、电流按已有视图分开展示，避免不同单位共用未标注的纵轴。每图显示纵轴数值与单位、横轴时间；曲线 2–3px，网格线细且中性。蓝色第二序列同时使用虚线或不同点形，并保留图例文字。

采样缺口保留断线，不插值、不补零；用中性区块与“无采样”文字解释。原始点和降采样后的点数按真实模型显示。光标或触摸查看点，同时提供键盘可操作的点选择控件，显示时间、数值与单位。无有效点显示文字空状态，不画水平 0 线。

预览模拟曲线只展示一条功率序列；滑块读取 8 个模拟采样点。手机保持刻度字号，图表区域可局部横向滚动，整页不能溢出。正式实现可减少刻度数量，但不能隐藏单位与时间范围。

## 6. 主题交互与首次加载

正式设置项：跟随系统／日间／夜间，默认跟随系统。顶栏提供始终可见、带文字的外观入口；手机端放入可发现的外观菜单。预览仅提供日间/夜间对照，不代表已完成系统跟随功能。

只在本机浏览器保存偏好，例如 `zeekr.theme`；不写车辆设置、不调用控制接口。显式选择优先于系统，只有跟随系统时才响应系统配色变化。存储禁用或异常时降级到当前会话与系统偏好，不阻塞页面。多标签同步偏好，已有页面保留表单输入、筛选、选中记录及地图视角。

首次绘制前设置主题与 color-scheme，避免先闪白再变暗；登录页也要执行。同源静态资源白名单与未登录资源许可需要一并调整；不能让登录页主题脚本被认证拦截。此项是后续实现任务。

默认不做明暗渐变动画，减少闪动；尊重减少动态效果设置。加大文字预览只用于评审排版；产品是否增加字号设置，另行决定，不扩大本次主题功能。

## 7. 后续实现步骤

1. 将分散颜色归并为语义变量，覆盖 app.css、storage-management.css、login.css 和 JS 内联图形/样式；不使用全局滤镜或粗暴通配选择器覆盖所有文字。
2. 对新增主题解析逻辑先写测试：非法偏好、存储异常、系统切换、显式覆盖、多标签变化。
3. 加载前初始化主题；接入登录与仪表盘入口、外观选择、系统监听。补静态资源及认证路径测试。
4. 逐页面迁移卡片、状态、表单、图表、地图控件。刻度展示按真实坐标计算，不能照搬预览模拟值。
5. 检查复用与选择器优先级；清理重复覆盖。只对已验证需求添加代码。
6. 验证后再进入提交/发布阶段；本设计不授权部署。
