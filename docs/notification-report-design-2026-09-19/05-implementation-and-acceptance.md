本文件是后续模型的实施指引，不是本轮已做修改。先读README和01–04；仅设计文件存在，不能据文档勾选实现通过。

## 2. P0：先固定基线与公开出口

### 2.1 先行工作

1. 核对当前HEAD、dirty文件、本地指令、现有测试。不覆盖用户未跟踪快照及原handoff.md。
2. 为当前重复停车缓存完成确认、终点冻结、途中/停车后充电区别补特征测试，记录文档漂移。
3. 在扩展summary之前，修复`monitor_runtime.read_status → WebApplication.state.monitoring`完整summary透传。
4. 对原`EventStore.query/latest`继续保留公开字段白名单，不因新增报告扩张API。

### 2.2 公共投影契约

`monitoring.events`最多给前端现有必要字段：`kind, delivery, created`及经处理的安全错误类别/固定文案；如前端确需摘要，只能从`events.PUBLIC_FIELDS`明确选取。不得返回完整summary、message、report_v2、地址、定位、原始signals、车辆标识或比较候选ID。

`monitoring`顶层同样显式选取前端需要的健康状态、心跳/采样时间、interval、trip/charge状态和安全错误；不能只清理events后仍把health任意未来字段整体透出。

公共查询必须按已认证会话当前选择车辆过滤；未认证或当前vehicle_key未知时events为空。绑定车辆不等于当前选车，不允许“没选车就返回所有车”。内部CLI如需私有诊断应独立函数/模式，不能让Web复用默认完整对象。

验收同时检查`/api/state.monitoring`、`/api/state.recent_events`、`/api/events`及轨迹接口。完整报告只在本地私有数据和已配置的企业微信正文中；不新增公共报告HTTP端点。

## 3. P1：字段契约、持久化及升级

实施02的纯解析和能力注册；新增03的规范化采样、活动状态命名空间及report_metric_index。迁移仅加表/索引/可选字段，事务幂等；不删除、重写全部历史事件或自动重发。

升级矩阵：

| 对象 | 升级策略 |
|---|---|
| v1已完成事件 | 保留flat值和正文；没有新参数就未知，不事后回填 |
| v1活动行程/充电 | 旧状态可读；新遥测统计标upgrade_mid_session；保留原始起止和事件身份，禁止把新统计说成全程 |
| v2活动会话重启 | 恢复profile、样本/累计器和停车候选；最后已处理样本去重 |
| v2活动会话跨不兼容解码/公式升级 | 标版本中途变化；不混算受影响差值/均值或用于历史比较，保留基础事件 |
| 已sent/failed/uncertain事件 | 状态和已存正文不改；渲染版本升级不重置delivery |
| v1 pending，已有发送尝试或地址已解析 | 沿用已存message，逐字节不变；不能因缺renderer_version就重渲染 |
| v1 pending，从未尝试且地址未解析 | 按原有v1模板和原事件位置完成首次地址准备，落盘正文；不得套v2或加新采样 |
| v2 pending，正文未冻结 | 只用已冻结报告/原坐标，按锁定renderer版本首次准备正文 |
| v2 pending，正文已冻结 | 即使代码升级、配置变化、后来历史增加，重试仍逐字节复用 |

无schema版本视为v1。未来未知版本不能按v1猜字段；保留基础flat摘要并将扩展报告标不可用，不能触发删除或自动重发。

事件ID沿用`sha256(vehicle:kind:start_time)`；报告版本、模板版本、观测次数不加入ID。旧/new字段冲突以已冻结flat基础事件契约为底线，不让renderer反向覆盖事实。

## 4. P2：模板与发送准备

按01实现三类详细模板和部分/缺失/陈旧分支。提供本地离线预览入口或测试fixture渲染器：读取合成事件或显式选定的私有已存事件，不启动采集、不调用sender、不读取Webhook。公开测试只用假数据。

具体发送顺序：

1. 按现有CAS将pending认领为sending；单工作者规则不变。
2. 若正文未冻结，读取事件已冻结报告；地址按原位置解析一次，超时/无Key/失败为未知。
3. 用事件锁定renderer生成预算内文本，记录省略项、版本、摘要和冻结标记，同事务保存message及地址结果。
4. **正文持久化成功后**才调用sender；地址或渲染阶段不得查询车辆、当前档案或最新历史。
5. 按现有投递结果写状态。重试不再渲染、不再解析地址。

本地确定的不可恢复渲染错误发生在sender之前，可标failed并用固定诊断文案；不能当网络不确定自动重试。若进程在sending阶段退出且无法确定是否已调用sender，仍按现有保守规则uncertain，不自动补发。报告异常尽量先降级核心模板，避免走失败分支。

不以“需要更详细”改成markdown/card、不拆多条、不发送私密外链。最终正文<=2048 UTF-8字节，目标1900；sender硬限制仍作最后保护。

## 5. P3–P6：依次丰富报告

### P3：行程与停车

- 加续航差、平均/采样最高速度、受门槛控制的估算能耗/达成率、温度/四轮参数。
- 独立冻结结束点与停车确认快照，样本归属按03。
- 别把新鲜整车时间当所有温度字段更新；别把重复缓存当锁车新确认。

### P4：充电过程

- 同侧同观测U/I、活动组合、剩余时间先接；平均/峰值/前后段变化后接。
- 缺口、无效点、0A停止点按03排除；输出覆盖情况。
- 目标、插枪、停止原因、真实电池温度不猜，默认走02门控。

### P5：历史与提示

- 实现04的同车、有界、版本一致筛选；每项独立样本数。
- 历史失败仅删比较块；提示先支持可靠普通状态和未确认文案。
- 已有关闭编码只证明关闭，未核验打开/未锁编码不能启用提醒。

### P6：候选能力

- 为02候选项补注册结构、disabled/default文案、合成正/反/缺失/冲突测试、人工核验步骤。
- 无证据的规则继续关闭；项目可交付其余功能，不用猜码“完成所有字段”。
- 不新增配置页面、任意公式执行或车辆操作；需要新的采样证据时在交付列出具体场景。

## 6. 发送、采样与隐私不变量

- 现有进程锁、查询冷却/退避、共享缓存、车辆绑定保持；报告不得扩大车辆请求。
- 暂停采集当前也暂停待发处理；本轮不顺手改暂停语义。
- 已明确成功不重发；超时/HTTP5xx/格式未确认及发送中崩溃维持uncertain；明确暂时拒绝最多六次尝试。不能宣称绝对不重不漏。
- 地址失败不压住其他报告；重试复用第一次冻结的地址/文本。
- Webhook仍只存在私有配置，错误和日志不含密钥；报告不含VIN、原始坐标、账户标识或登录链接。
- 新字段、历史查询、迁移、预览、测试不发真实群消息。
- 历史与报告数据默认保留；回滚不删表、不清delivery状态、不移走整库来绕过兼容问题。

**回滚兼容是发布门槛。** 不能把已扩展的数据库交给基线`1fad4c6`直接运行旧Web：它的完整summary透传会再次暴露report_v2。可运行的回滚目标必须包含P0公共投影/选车隔离，并识别v2正文冻结规则；对未冻结的v2待发事件，要能用锁定renderer准备，或明确暂停其投递并保留pending，不能套旧模板。没有这样的兼容版本，就停止会读取/发送这些事件的相关服务并保留数据库，直至兼容代码可用；不能以旧Web继续开放作为回滚。演练必须在合成库重跑公开出口及冻结正文测试。

## 8. 验证与交付步骤

每阶段先跑相关测试；完成后执行仓库Python离线测试：

```sh
python3 -m unittest discover -s tests -v
```

若修改前端，再跑相关Node语法检查和现有合成UI测试；纯后端报告不为凑检查而启动真实Web后台。浏览器验收用`tests/web_fixture.py`等合成环境，先确认其不会连接真实账户。

额外产物：三类正常报告、部分报告、旧缓存停车报告、全参数超长降级报告的**合成预览**，标明UTF-8字节数；数据库升级/重启/回滚演练日志；上述ID的测试映射。不把真实私有消息/坐标拷进仓库fixture。

## 9. 后续实车验收方向

此处仅指导，不代表本轮或接手实现默认有真实操作授权。

| 目标 | 待授权后需记录的证据 |
|---|---|
| 停车状态 | 正常行程、下电、用户自然锁车/关窗过程的云端状态与时间；旧缓存时诚实降级 |
| 充电过程 | 正常开始/持续/停止，U/I与车机对照；停充未拔枪与拔枪分别取样 |
| 目标SOC | 同一次会话有效目标及变化、对应SOC；仅历史截图不够 |
| 门窗/锁反向规则 | 每个相关对象实际开/闭、锁/解锁与未知/缺失样本；不要只测关闭 |
| 连接/原因 | 插枪未充电、活动、停止仍插枪、拔枪的独立证据，原因不能由时序臆测 |
| 电池温度/报警 | 必须取得明确对象/单位/状态映射来源，再实测；缺证据则继续禁用 |
| 群消息 | 用户明确允许后，单独发送标识清楚的测试；记录手机实际换行/长度/收信，不以API成功替代实收 |

授权实车验收时，避免为了采样而制造危险状态；可用既有只读记录先验证。部署需重新核对服务器、版本、备份和运行实例。当前只交设计，不运行`monitor --once`、不启动生产采集、不改服务器、不创建Git提交或push。
