# 自动行程与充电通知

后台默认每 30 秒读取缓存车辆状态（含停车），可在设置中改为 10–60 秒整数，并将每次成功读取发布到私有最新快照；故障和限流仍按原规则退避。起步、充电开始保留相邻可信状态限定的时间范围、首次活动样本与系统首次发现时间；没有完整证据时保留未知，不把缓存更新时间当精确开始事件。有效车速或连续里程增长触发行程记录；明确下电后，新的连续观测确认经过十分钟，才发送总结。充电开始与停止分别发送通知。网页与监控共用同一采集任务及车辆绑定；关闭网页不停止，网页暂停会同时暂停自动检查、轨迹记录和通知处理。后台确认进入暂停后，进行中的活动保留缺口和部分记录标记，恢复时不跨缺口连线或计算充电覆盖；停车确认从恢复后重新计时，有下电、未充电、同里程且无运动的证据时保留原到达时间。Web 或监控服务重启后默认开启，并保留已保存的间隔。Web 没有独立定时采集；进程锁保证同一目录只有一个执行者。

后台内置客户端在取得查询保护、完成请求准备后，真正发出请求前再次检查暂停或退出。取消按未发送处理，不升级为账号认证故障；取消自动续期也不会误耗刷新凭据。已发出请求返回的有效车况仍保全，手动读取保持原行为。

等待查询保护期间，采集配置若变成损坏 JSON、非法间隔或不安全权限，请求前检查会停止新请求，健康状态标记为配置不可用并保留采集缺口；不阻断账号、不发送重新登录告警。自动续期在此处停止也按未发送处理，保留刷新资格。修复配置后可继续采集，原查询间隔和限流冷却仍生效；不会擅自重置配置或修正权限。

查询缓存权限、数据库或查询锁在请求开始前不可用，也按本地未发送故障延后重试，不误判账号失效、不消耗刷新资格。缓存文件保留原样，禁止绕过查询保护。请求开始之后发生的响应或存储故障不据此推定为未发送；自动续期仍保留原来的不确定结果保护。

已保存的采集开关只接受字符串 `true` 或 `false`；空值、拼写错误或其他值会报告配置错误，不默认为开启。旧配置没有开关字段时仍默认开启；修改配置须通过设置页或显式写入有效配置，后台不会自动修复损坏值。

所有采集设置写入共用私有 `sampling-settings.lock`，锁内读取需要保留的字段并原子替换配置，避免不同进程互相覆盖。网页“保存间隔”只提交间隔操作，保留服务端最新开关；旧版完整开关／间隔提交仍按显式完整设置处理。锁持续忙时返回 HTTP 503，已有配置不变；写入失败不重复执行，进程退出由系统释放锁。

设置中的通知状态按来源隔离损坏记录。单条周期报告正文超过 2 MiB UTF-8、JSON 过深或格式损坏时，跳过该条并标记统计不完整，其余有效报告、车辆通知及认证告警仍可查看；不会修改队列或触发发送。存储巡检状态的深层损坏也只影响该来源，不拖垮整个通知诊断。

尚未连接车辆账号或尚无当前账号的车辆缓存时，通知诊断显示对应的连接／等待提示。账号或车辆上下文变化会清除旧诊断结果；建立上下文后可重新读取，失败提示与重试按钮保持可用。

页面与通知诊断共用心跳在线判断：心跳须为有效正数，缺失、非有限值、负数或未来时间不算在线。下次检查时间损坏不能无限延长旧心跳；忽略该值，仍按采集心跳默认三分钟窗口判断。有效的退避／冷却等待继续保留原宽限，停车缓存陈旧与后台离线仍分别判断；诊断读取不改写健康文件。

最近采样、新增观测等时间超出可表示日期范围时显示“未知”，不阻断状态页，也不改写原始健康记录；不会将异常时间解释为正常在线。

事件列表与最近行程／充电只读取当前用户私有目录中的普通数据库文件，不跟随文件或父目录链接，不接受硬链接或开放给其他用户的权限；不会自动修改权限或创建缺失目录。最近两类事件在同一个读取事务中取得，避免并发写入时拼出一旧一新的组合。事件库不可用时，页面仍保留车辆缓存，并单独提示本地事件不可用。

公共采集状态中的事件元数据单独校验：无效时间显示未知，未知事件类型显示为通用事件，非法投递状态显示为结果待确认。单个字段损坏不删除整条事件，也不让车辆状态接口因非有限数字或二进制字段而失败。已有合法状态、缺少的可选通知通道及原始数据库保持不变。

最新状态先按车辆时间判断；同一车辆时间的内容修订，再按实际获取时间、观测时间排序。晚到的旧读取不覆盖已接受状态，事件处理也使用已接受快照。完整读取仍保留归档；重复内容不增加修订号，但独立保留获取顺序高水位。

本地最新快照校验失败时，网页保留已有显示或空状态，并提示缓存错误。时间和修订号也须通过校验，即使修订号与页面已读版本相同。正文损坏可由有效重读修复；排序时间或版本元数据损坏时，拒绝猜测顺序或覆盖现有快照，应先检查、修复存储。失败前已成功取得的真实读取仍留在历史归档。

新报告的历史比较逐条排除异常旧记录。超过2 MiB的历史正文不载入解析器，JSON嵌套过深的记录单独记为不可用；其他有效候选仍可参与比较。旧记录不改写，不因某条坏记录放弃整组可用样本；比较之外的异常仍由新事件原有兜底处理。

当前报告与历史样本使用同样的版本资格限制：片段、升级途中或解码版本中途变化的报告不生成历史比较。当前报告已不合格时，直接返回，不读取可选历史；已观测的基础里程、时段与事件仍照常保留。

历史比较的纯计算异常可只降级比较块；同一结算事务内的数据库或文件存储错误必须向外抛出，回滚本轮活动状态、报告观测、事件及通知队列写入。不能把已撤销的事务当成可继续提交。存储恢复后可重试结算，不因这类故障提前清空进行中的行程或充电；独立轨迹读取不宣称与结算事务原子提交。

## 配置和启动

将已创建的企业微信群机器人 Webhook 保存到应用数据目录的 `wecom-webhook.json`，字段为 `webhook_url`。应用数据目录必须归运行用户所有且权限 700，文件权限 600。不要把此文件放进 Git、截图、日志或命令行参数。

本机应用数据目录是 `~/Library/Application Support/ZeekrControl`；部署模板的服务用户目录是 `/var/lib/zeekr-control/Library/Application Support/ZeekrControl`。

```bash
python3 -m zeekr_control monitor
python3 -m zeekr_control monitor-status
```

首条命令持续运行；第二条只读取状态，不查询车辆或发送消息。`monitor --once` 会检查一次车辆并处理待发通知，不是无副作用的测试模式。单车首次自动绑定车辆摘要；多车首次使用 `--vehicle 序号`。绑定后按身份选择，不因列表重排或换账号而静默换车。确认换车时停止服务并备份、移走 `monitor-binding.json`，再明确选择新车。

企业微信通知使用 Markdown 显示充电地点、行程出发地和到达地的中文地址，不含 VIN、经纬度、账号或登录链接。地点优先使用端点可信定位；缺失时可使用此前五分钟内的可信定位，并注明参考时间。已结束的完整行程若仍缺少地址，可复用页面通勤识别的同一份账号、车辆及规则版本证据，以“家附近（通勤规则推断，非精确起点）”等文字兜底。手动排除、未匹配、部分行程及缺少完整证据的旧结果不作兜底；开始通知不等待未来采样，也不提前推断目的地。推断仅用于文字，不更改原始定位、轨迹或里程。首次发送前冻结地点与证据，重试及历史预览保持原内容，不重发既有消息。

地点命名优先使用当前账号、车辆下适用的已保存标注，再使用地图解析地址。充电通知复用充电页面的地点、站名确认：“仅本次”只用于对应记录，“同地点”须满足原有位置匹配范围；尚未确认的参考候选不会自动采用。行程通知复用页面的边界采样、停车证据和命名区域匹配；多边形重叠冲突不猜选。通勤规则中的家／公司中心若唯一关联已命名区域，推断文字也优先使用该名称，并继续标明“通勤规则推断”。“已标注地点”“参考定位”“停车证据推断”“本次充电已确认，无可信定位”分别保留证据性质；标注只改变通知文字，不补造 GPS 或轨迹。名称修改仅影响尚未冻结的新消息。

行程正文成功后另发一张 PNG：地图显示有效可信采样形成的分段轨迹、首末采样点和真实道路底图，下方保留里程、耗时、SOC 与估算能耗。地图缺失或地图服务失败时不发送伪造底图，也不重发正文；完整轨迹仍在现有网页中查看。

## 服务器服务

在已准备代码和配置的服务器安装 `deploy/zeekr-monitor.service`，然后：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zeekr-monitor
sudo systemctl status zeekr-monitor --no-pager
sudo -u zeekr-control env HOME=/var/lib/zeekr-control sh -c 'cd /opt/zeekr-control/current && python3 -m zeekr_control monitor-status'
```

网页设置页显示后台健康状态和最近通知。`stale` 表示缓存太旧，`unchanged` 表示未取得更晚的车辆状态，均不代表车辆当前静止。网络故障、临时 HTTP 错误和坏响应退避重试，429 遵守冷却。1509 先用原凭据探测；持续失败达到门槛后，仅在已启用并验证续期规则时尝试自动刷新，实际目标车辆读取成功才确认接口恢复。刷新结果不确定或明确拒绝时，不重放该刷新凭据，继续受保护的读取探测并提示必要的人工认证；不能仅凭 1509 判定必须重新登录。明确的鉴权或配置错误仍须处理后恢复。Mac mini 使用已配置的本机钥匙串连接入口，不手工复制 Token；其他部署的会话须以实际服务用户权限保存。

停止和恢复：

```bash
sudo systemctl stop zeekr-monitor
sudo systemctl start zeekr-monitor
```

仅停止独立监控时，运行中的 Web 可接管采集。完全停止需同时停止 `zeekr-control` 与 `zeekr-monitor`，或使用网页暂停。停用开机自动运行需同时禁用这两个服务。独立监控不更改网站、SSH、Nginx、防火墙或公司官网配置。

## 数据准确性

- 云端缓存延迟会推迟通知。行程首次下电端点已冻结后，特定的同一停车缓存可用连续本机观测时间完成十分钟确认；重复读取不产生新参数样本、不刷新停车状态时间，也不证明车辆在确认时仍保持该状态。
- 里程以起止总里程差计算，耗时含途中堵车和等灯，不含结束后的通知等待时间。只有部分观测时注明不完整。没有 kWh 数据时仅报电量百分点，不能把电池容量乘电量变化当作精确耗电。
- 下电要求 `engineStatus=engine_off` 与 `ptReady=0` 同时满足。上电或未知状态会取消当前结束确认，行程保留；有效移动证据不会被零速/旧动力状态覆盖。
- 电流、电压回充不能单独识别外接充电（可能涉及动能回收或缓存）。直流充电采用本车已核验组合：直流口盖 chargeLidDcAcStatus=1、chargerState=24、dcChargeSts=12，且桩侧电压与桩侧电流均有效且大于零。交流充电采用2026-09-19补证的独立组合，见[交流充电核验](ac-charging-validation-2026-09-19.md)。明确文字状态或配置的充电状态码仍使用既有直流口盖门控。与有效行驶/动力就绪信号冲突时保持待确认。首次观测就处于充电中时，不声称知道真实开始时间。
- 直流组合优先，不能被通用充电码、连接码或通用电流为零覆盖。已核验的直流停止组合为：直流口盖1、chargerState=26、dcChargeSts=10、合法桩侧电流0，且没有非法直流字段、行驶或动力运行冲突。它只证明匹配停止观测，不证明达到目标、停止原因或已经拔枪。两种口盖现均已核验1=打开、2=关闭；口盖不代表插枪。交流停止、预约、插拔状态与目标电量仍待证据。
- `--charging-active-code` / `--charging-stopped-code` 只接收本车实测核验后的 `chargeSts`，可重复提供。社区枚举明确标为经验性，不作为所有非零状态均为充电的依据。字段参考：[固定版本解析器](https://github.com/RexzeLu/zeekr_ha/blob/316ce6e7ea718b3d5ba4597bf87627904add5330/custom_components/zeekr_ev/parser.py)。
- 轨迹为有效缓存采样点；不反推未采集路段。状态和通知存入现有私有 `tracks.sqlite3`，Webhook 不进入数据库。
- 坐标超出所用整数刻度的地理范围时，定位标为无效，保留定位缺口；其余有效里程、电量与行程状态继续记录，位置异常不丢弃整次观测。
- 可选指标在转为浮点数后仍须为有限值；异常胎压等数值记为缺失，不把溢出的无穷值写进行程遥测。已有字段范围与解码规则保持原样。
- 温度更新时间有效不代表温度值有效。缺失或越界的温度仍标为缺失；计算温差时重新核对两端实际数值和时间，旧存档里的错误有效标记不阻断行程结束。
- 胎压、胎温差值也重新校验实际数值，跳过错误类型与非有限值。胎压原值为 0 时仍保留原值，但按报告契约不计算涉及该端点的胎压差值；这不改变胎压告警阈值或确认规则。
- 额定续航达成率使用事件冻结的额定续航、标准、里程与 SOC，不依赖电池容量配置。仍要求完整记录、里程至少 10 km、SOC 下降至少 3 个百分点且无途中充电污染；容量未知时，kWh 与百公里耗电估算保持未知。

## 连续用车场景

已知采集中断或后台确认暂停后，自定义提醒和胎压提醒均重新累计连续确认；中断前已生效的告警状态、冷却时间和发送结果保留，恢复采集不等于条件恢复。

自定义提醒在准备与实际发送前都核对当前规则、最近确认事件及条件。关闭、修改规则或条件恢复后，过时任务在发送前取消。准备中断可重新核对后续发；实际发送结果未确认时不自动重发。有效期按单调时钟累计投递等待耗时，包含前序阶段、恢复、准备及事务等待；认领发送前已过期的任务取消。

回家后立即充电时，行程与充电分别记录：首次下电时冻结行程终点，充电开始可先发通知，停车确认满十分钟后再发行程报告。停车后的补电不改写到家电量。途中短停补电后继续开则属于行程内充电，不输出驾驶电量变化或耗电估算。停车候选后继续有里程增长，即使采样车速为零，也取消该停车候选。

短停期间的有效观测在恢复行驶后计入行程；最终停车确认期观测只用于停车状态，不占行程统计。充电状态未知或电流瞬时为零时，不凭此生成停止/开始事件；未知观测也不能被跳过后计算连续功率覆盖。插枪、预约等待、停止但未拔枪、目标达成及交流充电的能力边界见[用车场景矩阵](vehicle-usage-scenarios-2026-09-19.md)。

## 通知可靠性与验证

成功响应写入后不会重发。明确的临时拒绝退避重试，最多六次；永久拒绝标记失败。文字、Bark、图片各阶段按累计耗时判断待发任务；失败后的等待从本次返回后起算，发送确认时间记录实际完成时刻。超时、无效响应或发送中进程中断标记 `uncertain`，人工核对群内事件编号后处理，不自动重复发送。群机器人没有客户端幂等键，不能承诺绝对不丢且绝对不重复。

车辆 Bark 通知先准备内容，临发送再核对暂停、账号、车辆与执行预算。准备期间取消不会调用发送器、不计发送次数，任务保留待发；准备失败与实际发送后结果未确认分开记录。

1509 告警也在准备完成后核对中断是否仍有效及采集开关。准备期间已恢复或被新提醒替换，旧通知取消；准备中断可续发，实际发送后结果不明则保留状态，不自动重发。

1509 通知队列和采集中断事件库分别在事务内初始化表、字段与索引；建表或升级语句失败时回滚，不留下部分升级，也不自动删除冲突的旧记录。

首次绑定前发生的 1509 中断保留“车辆未绑定”归属；同账号的目标车辆实际状态请求成功且结构有效后，同时记下该早期中断的恢复时间。车辆列表成功或本机缓存命中不能确认恢复，也不改写其他账号、其他车辆的中断。

## 中文地址配置

地址和行程静态地图使用高德 Web 服务。进入高德开放平台「应用管理 → 我的应用」，创建应用并添加 **Web 服务** 类型的 Key（不是 Web 端 JS API Key）。官方说明：
https://lbs.amap.com/api/webservice/guide/create-project/get-key

在监控实际运行的应用数据目录保存 `amap-geocoding.json`：

```json
{"api_key": "你的高德 Web 服务 Key"}
```

目录权限 700，文件权限 600，文件所有者须为运行监控的用户。服务器目录是 `/var/lib/zeekr-control/Library/Application Support/ZeekrControl`。不要将 Key 放入 Git、命令参数或日志。Key 每次解析时读取；已运行新版监控时，配置更新无需重启。

仅在新通知发送前将事件对应的有效、可信坐标发给高德。地址请求使用起终点；行程图片请求使用最多四段、合计最多 120 个采样点，保留每段首末点。WGS84 先使用高德坐标转换接口，GCJ-02 直接使用；未知坐标系不猜测。地址为坐标附近的地图解析结果，不保证准确识别具体充电站或建筑。充电采用开始观测的位置，行程采用起点与冻结的结束点，不使用发送时的当前位置替代。事件保存解析后的地址，发送重试复用同一文本。每次地图请求超时 5 秒；失败、缺少 Key、历史事件缺少定位均不阻断正文通知。

此配置使有效事件坐标发送至高德，并将解析地址及高德静态地图发送到现有企业微信群。原始坐标保留在私有监控数据中。旧事件不自动补位置或重发；不通过当前车辆位置推测历史地点。
