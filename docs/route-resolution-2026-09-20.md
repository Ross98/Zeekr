# 轨迹采样密度与道路展示

## 已批准的方向

核查更密的云端原始轨迹；展示采样间隔和可信连线跨度，稀疏连线明确作为示意；高德道路匹配仅作为有条件的可选推测图层，保留原始点、缺口和原始里程。

## 先核查、再实现

1. 当前绑定车辆的云端历史会话缺少四项专用字段，状态为 `authorization_required`。没有用状态会话冒充历史授权，没有尝试登录变体；尚无法验证云端历史的点密度。
2. 高德 Web 服务配置存在，但这不证明轨迹纠偏接口权限可用。现有本地轨迹不包含经核验的逐点 GPS 时间、速度和方向，坐标系解释也待实车对齐。当前数据不能直接当作满足纠偏输入条件。
3. 本轮先落地不依赖以上条件的采样密度提示与示意线；不接入伪造速度、方向或采集时间的纠偏请求。
4. 用户另授权一次有次数和时长上限的状态查询频率测试。只对当前账号、当前绑定车辆做状态 GET；临时跳过本地 60 秒缓存和账号间隔，保留跨进程锁、服务端 429 冷却、异常即停。正式采集频率不变。结果另记。

## 实现计划

- 先写纯 JS 测试：相邻时间统计、未知/倒退时间、可信片段距离、缺口不跨越、稀疏与较密相邻边分组、边界点保留、非法坐标排除。
- 增加本地与云端共用的采样密度展示模块；只计算已返回的位置数据，不新增坐标请求或外部请求。
- 时间统计使用原始顺序中相邻、有效、递增的源状态/轨迹点时间，不把本机观测时间替代成 GPS 时间。
- 距离统计只计算现有可信片段内部相邻点的球面直线距离，不跨缺口；不能当作实际行驶里程。
- 相邻点超过 10 秒或 100 米时将其连线标为稀疏示意，用虚线表示。此阈值是可解释的显示策略，不是 GPS 精度判定或极氪接口限制。所有连线都不保证实际道路形状。
- 保留所有已有采样点、首末标记、断线、回放、地图视角与隐私开关；新模块不改变 API、数据库、采样频率、通知或里程统计。
- 新脚本进入认证静态文件白名单。浏览器用合成轨迹验证本地/云端、明暗主题、320/390/1440 px、隐私开关和迟到请求。
- 完成后复核重复计算和共用逻辑，运行有关 Python/JS/浏览器回归。

## 高德匹配后续条件

官方轨迹纠偏文档要求位置、时间、速度、方向；说明 5–10 秒采样为理论较优密度，过少或稀疏的点可能失败：
https://lbs.amap.com/api/webservice/guide/api/grasproad

接入前需核验源坐标系、逐点时间及运动字段，申请/确认对应权限，并确认匹配结果在使用的底图坐标系下正确对齐。用户手动开启后才发送所需点；推测结果单独标识，不能覆盖原始轨迹或用于回写实际里程。缺口不得以未经验证的路线自动补齐。
