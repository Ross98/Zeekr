# 行程与充电起点准确性

## 目标与证据

用户要求完成 60 秒采样、起点证据分级、实际误差核验方案。变更前代码停车后 300 秒采样，连续观测门槛 180 秒；起点采用缓存样本，不能当作车辆实际开始事件。交接文件早于当前 `e018a67`，以该版本代码为基线。

## 实现计划

1. 先补回归：停车和旧缓存也保持 60 秒；暂停、故障退避、限流、重复缓存规则不变。
2. 保存并公开投影 `start_evidence`：相邻可信状态圈定范围 / 首次看到已活动 / 历史证据缺失。车端状态时间、服务器首次发现时间、样本年龄和发现延迟范围分开。实际开始事件尚无已核验来源，`actual_start_time` 保留空值。
3. 起点证据随会话重启、结束事件持久化。保持原统计起点、电量、里程、轨迹和稳定事件编号，不用推测时间拼接虚假参数。
4. 行程详情、当前充电、历史充电及通知展示证据。所有嵌套字段显式白名单；历史记录只读降级，不批量改写或补发。
5. 提供只读核验工具：当前绑定车辆事件，对照可选的人工实测开始时间，输出有符号记录误差、发现延迟、样本年龄及范围命中；没有实测基准时不声称测得真实延迟。不输出车辆标识、坐标、原始负载、消息或凭据。
6. 运行 Python 回归及相关浏览器验收，检查窄屏和历史兼容；再复核实现能否简化。

## 验收标准

- 正常采集始终 60 秒；仍遵守查询缓存、网关限流、故障退避和暂停。
- 行程/AC/DC 充电起点范围只来自相邻且新鲜的可信状态；缺口、未知状态、首次就活动、旧版本会话不能伪造范围。
- 重复/倒退缓存不改写首次发现时间；发现时间不采用通知发送或结束事件创建时间。
- 样本年龄不能称为真实开始延迟；时钟冲突不产生负延迟结论。
- 起点元数据不改变统计里程、电量、时长与事件去重；新旧 API 均不暴露私有字段。
- 页面和通知明确区分记录起点、可能开始范围、首次活动样本、系统首次发现。历史无证据时显示未知。
- 实车改善幅度需同次实测基准与记录核对。离线模拟不能代替实车证据。

## 使用只读核验工具

工具默认使用本机应用数据目录及当前绑定车辆。服务器新版代码已安装，可在当前版本目录以实际服务用户执行；不启动 `monitor --once`。

```bash
python3 -m zeekr_control.start_audit --days 7 --limit 20
python3 -m zeekr_control.start_audit --event EVENT_ID --actual-start '2026-09-20T08:00:30+08:00'
```

`EVENT_ID` 使用第一条命令返回的事件编号，实测时间需含时区。输出含：

- `record_offset_seconds`：记录起点减实测开始，可为负（行程起点保留前一停车样本）。
- `detection_delay_seconds`：系统首次发现减实测开始；没有首样本或实测基准则为空。负值保留供检查时钟/基准冲突。
- `reference_within_bounds`：实测基准是否落入相邻可信观测区间；无范围则为空。
- `sample_age_*`：仅首活动样本的年龄，不能代替真实开始延迟。

人工基准仅用于本次只读对照，标为 `user_supplied`，不写回车辆事件，不改变任何统计起点、里程、电量、轨迹、通知或事件编号。事件必须属于当前绑定车辆。
