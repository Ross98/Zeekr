# 以产品问题为入口的参数研究

当前执行清单见[参数研究落地清单](parameter-product-backlog.md)。全目录用于查询和保留历史证据，不再作为必须逐项解出的任务。

## 开始研究的条件

先写清：用户遇到的问题、修好后可见的行为、验收方式、必需参数、能改变实现决定的新增证据。没有具体产品问题，不因字段仍标“待确认”就继续研究。用户明确要求研究某字段时，仍先约定其可交付结果及证据边界。

已有证据足够支持保护性修复，就直接实现并验证，例如2046不应显示成几千分钟；不必等到厂家精确枚举齐全。已有证据无法区分候选，且没有独立对照时，记录缺口并暂缓。不要为相同输入另起专题、反复切日期或重查同类社区解释来制造进展。

每轮产出必须对应：完成的代码与验收、可以实施且有验收条件的方案，或明确重开条件的暂缓项。修订说明须标为说明修订；测试通过、部署完成、自然场景验收分别记账。没有证据变化时结束本轮，不新增“仍未确认”的研究报告，不自动建立轮询任务。

## 保留的证据要求

需要进入具体参数研究时，每项记录候选含义、已出现原值解释、研究阶段、专门证据和可证伪的验证方法；完整逐值解释及反例仍保留，避免把摘要当作完整码表。下述跨字段方法按产品问题选用，不要求逐项跑完。

新增专门比较：车窗状态与同侧位置、座椅通风状态与档位、安全带与独立行程、倒车灯与用户指定档位、充电状态与桩电流、DC/DC连接与激活、电池侧电流与桩侧电流、保养距离与里程、保养天数与日历、停车时间码与动力/P档边界、航向角与可信运动方向。航向比较仅输出统计，不输出位置。

研究阶段区分专门跨字段对照、场景对照、单一值、无有效值、已有部分解释。跨字段对照表示完成这项比较，不表示厂家或实车操作确认。缺值、空值、格式无效和有效原值分开计数；当前车型资料不能补作历史观测。

纠正过度推断：加热档位可能是保留设定；通风激活不保证设定非零；非充电连接码不证明DC/DC关闭；充电组合码不能仅凭名称当作准备态；湿度原值未标定，不自动转换百分比；电池温度等级的高低方向仍需证据。既有用户配置约束出现动态反例时必须重新核对。

推测只进入研究记录，不自动修改运行解码、通知或历史活动。真实研究载荷及含数值的完整清单保留仓库外；合成桌面检查与生产真实归档只读核对分别记录。

## 电池侧电流解释补充

`dcChargeIAct` 按本车历史对照采用：正值放电、负值充电或能量回收，与桩侧电流分开解释。起充过渡帧可能存在电池侧与桩侧读数不同步；不以单帧正负独立判定充电状态，应结合后续连续样本、桩侧电流及 SOC 变化。行驶负值符合电池回充，但不能仅凭它区分松电门回收和制动回收。

参数词典、逐项研究与充电详情共用词典说明；假设逐值解释保留过渡提示。只更新解释，不改原值、充电判定、功率统计、通知或已有人工核实记录。

## 两组行程小计规则补充（2026-10-22）

车主明确确认本车 OS 5.6 的仪表使用规则：行程1停车后重置，行程2充电结束后重置。所附中文手册截图的共同限制为：任一行程行驶距离达到9999.9 km，或行驶时长达到999小时59分钟，两个行程数据同步清零。车主确认与手册截图分别标明来源；不将车主提供的行程对应关系写成截图原文或厂家接口定义。

返回字段 `tripMeter1` / `tripMeter2` 的编号不直接等同于仪表行程1 / 行程2。近30天本车归档中，A未见回落且期间包含充电；B可在长停后先返回旧值、随后返回0。观测归零边界不能标定实际清零延时，不再将约4小时当作可用触发阈值。仪表与返回字段对应关系仍待核实；缺少同步仪表证据时暂缓索引映射，不继续用同一归档重猜。不修改原值、自动清零任何数据或改动已有人工核实记录。
