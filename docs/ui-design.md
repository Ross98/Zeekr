# Zeekr Web UI 设计方案

日期：2026-09-17。状态：用户已批准；本机 Web 首版已实现，云端历史接口待验证。使用与实际边界见 `web-usage.md`。

## 目标与依据

以已验证的字段规则为证据边界，面向兼容的极氪车辆。实现响应式 Web，覆盖车辆状态、地图定位、云端历史轨迹和后续位置采集。本地实车记录属于历史快照，不能作为实时数据源；示例数据必须显著标明演示。

继续复用 Python 认证和缓存读取链路。第一版提供信息展示，不提供车控按钮。云端历史轨迹尚未验证，不承诺一定能取得历史记录。

## 页面与导航

桌面端左侧导航、右侧内容；手机端底部设置“总览、车辆、地图、轨迹、更多”五个入口。能源、参数详情和设置从车辆页或更多进入。

### 1. 总览

顶部显示车辆名称、脱敏车辆标识、账号连接状态、手动刷新按钮；独立展示“本次读取时间”和“车辆状态更新时间”。刷新表示再次读取缓存，不表示唤醒车辆或获得实时数据。

首屏以动力电池电量、电池续航、总里程为主卡片。下方显示车内外温度及温度独立更新时间、已核对的锁车/充电组合摘要、四轮胎压和胎温。

布局草图：

```text
车辆名称                     连接状态   刷新
车辆状态更新：…               本次读取：…
电量                 电池续航              总里程
车辆示意 / 门窗摘要              四轮胎压与胎温
车内外温度 / 温度更新时间        最近位置 / 可信度
轨迹记录状态                    最近记录入口
```

总览摘要可以跳转到逐项状态。定位默认显示占位卡，用户主动开启位置显示后再加载地图；精确坐标文本默认隐藏。第一次访问无数据时显示空态，不用 历史快照数值填充卡片。

### 2. 车辆详情

官方车型图片配合文字列表。颜色仅辅助辨识，所有状态带中文文字。2026-09-17 桌面端优化按以下层级落地；本次不包含手机端专项优化。

- 顶部摘要显示整车相对更新时间、云端缓存提示、四门／四锁／四窗已确认数量，以及需关注和未知项数量。不以“需关注 0 项”推导全部正常；未知项独立显示。
- 主区域左侧为当前车辆配置对应的官方 PNG 车型图与四门文字卡；图片使用官方产品视角，四门文字卡按左前、右前、左后、右后排列，前舱盖、尾门和中控锁独立展示。右侧依次显示四轮数据与座舱环境。较窄桌面改为门窗区域在上、轮胎和座舱并排在下。
- 关闭／锁止使用绿色，已解释的打开／未锁使用琥珀色，未知使用灰色及明确文字。前端不扩展云端枚举解释；未核对的值仍为未知。车型图只展示外观，不叠加门窗开闭效果；全部状态通过独立文字卡展示。
- 门窗原值与解释依据、空调、座椅与方向盘、空气质量、待核实设备及完整时间默认折叠。刷新保留当前展开状态；折叠标题支持键盘操作。

- 四个车门分别展示开闭、门锁、车窗；正常状态也逐项展开。
- 中控锁、尾门、前舱盖独立显示，不从车门或车窗状态推断。
- 四轮按左前、右前、左后、右后展示 kPa 与 °C，保留接口小数。
- 温度显示自己的更新时间；空调、座椅、方向盘、空气质量另设折叠区。
- 未核实枚举显示“未知 · 原值 …”；布尔字段仅描述接口标记，不推导硬件正在运行。
- 天窗、遮阳帘、后排通风等硬件适配不明字段放入“待核实参数”，不画成可操作设备。

### 3. 能源与充电

动力电池与低压电池分区，完整数据路径在详情中可查。动力电池电量仅取 electricVehicleStatus.chargeLevel；低压电池电量和健康字段不得代替动力电池指标。

充电状态、充电器状态、充电枪连接状态分别展示。只有已核对三项组合才显示“未充电”，单项枚举不直接翻译成“未插枪”。电压、电流、直流字段、预约和放电字段保留原值与待核实说明；未验证单位不擅自补单位。

2047 显示“暂无有效时间估计”，null 和非法数值显示“未知”。平均电耗、瞬时电耗、小计里程、平均速度展示统计口径待核对提示，不用它们生成未经验证的费用、效率或旅程指标。

### 4. 地图定位

地图占主体，侧栏或手机底部信息卡展示：位置可信度、整车缓存更新时间、本次读取时间、坐标系解释状态。没有独立 GPS 时间时明确显示“定位采集时间未提供”，不把整车时间改名为定位时间。

- posCanBeTrusted=true：显示“接口标记可信”，不等同于已实地验证。
- false 或缺失：显示“位置未确认”；有效坐标可作为灰色候选点，不能冒充当前位置。
- 坐标非法或缺失：显示空态，不落在零点、不使用演示坐标替代。
- 坐标缩放与坐标系转换分别处理；整数除以 3,600,000、marsCoordinates 的社区解释需保留来源及验证状态。地图对齐验证前不宣称位置准确。
- speedValidity=false 时，车速显示无效，不由 0 推断停车；parkTime 不作为已确认停车开始时间。

地图提供查看、缩放、回到最近位置和位置隐私开关。底图供应商和密钥方式在实现前选定；加载外部底图会向供应商请求相应区域瓦片，位置显示应由用户主动开启。Token、VIN 和完整状态响应不发送给地图供应商。

### 5. 轨迹

同一页面分“云端历史”和“本地记录”两个来源，可用日期筛选。来源和覆盖范围始终可见，不能把本地记录伪装成云端历史。

云端历史：先确认端点、账号权限、分页、时间范围与返回字段。接口未接入显示“尚未接入”；无权限、请求失败、确实无记录分别展示，不统一显示“无行程”。路线点不足时仅展示可得摘要，不补造路线。

本地记录：提供明确的开始/暂停采集、采集状态、最近成功读取及最近新增位置时间。建议初始采样间隔 5 分钟，可配置；实际频率在接口限制和数据更新速度验证后调整。启动 Web 不自动开始采集；采集开启后由后端执行，浏览器关闭不应停止正在运行的后端。设备休眠、断网或服务停止期间无法采集。

原始观测与路线点分开存储：保存服务端状态时间、本机观测时间、原始坐标、标准化坐标、可信标记、来源及变换说明；GPS 时间未提供则为空。相同缓存重复读取不产生新定位点；相同坐标但时间更新可保留观测证据，避免误删有效停车记录。

路线只连接满足可信度和连续性规则的点。未知时间、低可信点和较长采集间断分段显示；不跨缺口画成完整道路，不做无依据的道路吸附。界面称“采样记录”，不声称完整还原实际驾驶路径。规则阈值应配置并记录在数据中。

支持日期列表、地图折线、时间滑块逐点回看。缺少 GPS 时间时，回看时间明确标注为缓存状态时间或本机观测时间。未确认的行程距离、起止时间与耗电不强行计算。

### 6. 参数详情与设置

参数详情按字段分类列出：中文名称、字段路径、原值、解释、单位验证情况、证据等级、可用更新时间。支持搜索与“仅查看未知”筛选。燃油、拖车、第三排、模块 null 等通用字段收纳在平台参数区，不能推断本车具备相应硬件。

设置展示账号状态、车辆选择、采样间隔、记录存储位置与容量、位置隐私开关。第一版复用终端登录与已有会话；未登录或会话失效时引导本机终端登录，不循环发送短信。若部署到服务器，登录入口与访问认证需另行确定。

## 通用视觉和交互

默认浅色：浅灰背景、白色卡片、深色文字、克制的蓝绿色强调色。地图和车辆指标占主要面积，参数说明通过详情展开，避免满屏开发字段。手机单列，桌面两到三列；字体、按钮和焦点状态支持键盘及触控操作。

“已核对”“接口返回”“待核实”“未知”与业务状态分开显示；待核实不使用表示正常的绿色。加载中保留旧数据和原时间；刷新失败显示错误与旧数据标签，不将旧值清空成 0，也不更新时间伪装新数据。

## 架构建议与部署边界

推荐复用现有 Python 后端，增加只读 JSON API、结构化字段解释层、SQLite 观测与轨迹存储、独立采集循环；前端采用 HTML/CSS/JavaScript 模块，静态资源由本地服务提供。地图作为单独模块接入，不要求引入完整前端框架即可完成首版。

相比独立 SPA，此方案部署环节少，适合现有小型 Python 项目；纯静态页面无法安全保存会话和持续采集，因此仍需要后端。以后界面复杂度明显增加时再考虑 React/Vue。

默认只监听 127.0.0.1。手机响应式布局不代表已开放远程访问；若部署到常在线服务器或需要手机跨设备访问，再配置认证、TLS 和访问范围。凭据只在服务端保存；浏览器不接收凭据。位置和轨迹数据库放在用户应用数据目录并限制文件权限，不写入项目仓库。

后端返回原始数据的脱敏版本与展示模型分离；精确位置经专门的地图数据接口提供，避免普通状态接口无意暴露位置。采集启停等有副作用的接口不得使用 GET，并校验来源及会话。

## 实施与验收

1. 状态展示：结构化解释层、Web 总览、车辆、能源、参数详情；验证与现有 CLI 的兼容性。
2. 地图：验证坐标解析和坐标系，在用户本机比对已知位置；未验证状态可明确显示。
3. 本地记录：SQLite、手动启停采集、去重、断点分段、日期筛选与回看。
4. 云端历史：独立核查接口权限与实际数据；成功后接入同一轨迹页面，受限时保留真实的能力状态。

测试重点：动力/低压电池区分；未知、null、矛盾状态；四门四锁四窗独立展示；2047；各字段更新时间；定位不可信与坐标无效；重复缓存去重；跨断点不连线；采集失败与会话失效；默认接口脱敏及凭据不进入前端。通过合成数据验证不能替代真实车辆位置、真实历史接口和长期采集验收。

浏览器验收覆盖桌面与手机宽度、无数据、加载、失败、旧缓存、长字段和键盘操作。设计快照中的数值仅允许用于明确标注的测试夹具或演示模式。
