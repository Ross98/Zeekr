# 可配置状态采集间隔

目标：默认从 60 秒改为 30 秒；设置可选 10–60 秒整数。采集、状态响应缓存与同账号状态查询保护使用同一私有配置。停车不降频。车辆列表和历史缓存仍为 60 秒。

短时探测在最低 1 秒阶段未触发 429，但不能据此认定长期额度。更快读取也不保证车辆上传更快；重复云端状态不新增轨迹点。10 秒是本项目允许的配置下限，不是官方接口极限。

实施顺序：

1. 先验证默认值、10/60 秒边界、跨进程缓存、失败请求保护、动态改频率与共享 429 冷却。
2. 提取采样配置；启动恢复采集时保留所选间隔。后台正常等待可重新计时，故障退避和真实冷却不被改频率缩短。
3. 设置页允许单独保存间隔；暂停/恢复保留已保存间隔；后台刷新保留尚未保存的输入。
4. 跑采集/API/查询保护测试和浏览器验收；检查变更、精简后提交。

边界：旧版本遗留的本机状态冷却最多先等完原窗口；新版本记录请求尝试时间，调高或调低间隔都按该时间重新计算。共享锁不变；429 的 Retry-After 不缩短，无有效头时仍冷却 60 秒；网络故障仍从 120 秒开始退避，最大 900 秒。

部署与实车效果另行验证。本地测试不能证明行驶时轨迹点会增加。

## 验证结果

- 完整 Python 测试 555 项通过；清理重复状态赋值后，再跑采集测试 20 项通过。
- 浏览器主流程通过：默认 30、拒绝 9、保存 10、暂停时改为 15、恢复保留 15；尚未保存的输入和焦点不被后台刷新覆盖。
- 云端历史浏览器验收通过，覆盖显式查询、权限状态、隐私、详情、分页、过期响应和四种宽度。
- 桌面、390px 手机设置页无横向溢出，检查浅色与深色截图；JS 语法、Git diff 空白检查通过。
- 全部自动化用合成数据；本轮未更改线上配置、未发起新的车辆限流探测。
