# 用车研究：以已获取数据的利用为目标

用户澄清：尽可能将已经获取的数据用上。验收重心转为数据覆盖、可解释性和实际用途。
此前 `codex/insights-experience` 的导航、报告与趋势优化是体验基础；不能作为全量数据利用已完成的证据。

## 本轮只读盘点

当前静态 `parameter_dictionary.json` 共 237 个目录条目，其中 217 项可展示，20 项受隐私过滤。
可展示条目的目录类型：161 项 enum、41 项 number、4 项 boolean、8 项 timestamp、3 项 text。
这些是目录定义，不证明实车已返回、值有效、设备已装配或枚举含义已确认。
本轮未读取真实账号归档，尚不能给出真实数据利用率。

已核对的现有能力：

- `vehicle_parameters.py` 与车辆页面按安全目录展示当前快照，区分已解释、待核实、空、无效和未返回。
- `archive_reader.py` 支持安全字段的历史回看、两条快照差异；参数实验室可冻结前后样本、实际动作与备注。
- 参数字典保存字段/具体原值的人工核实注释，实验室保存一次动作涉及的一组字段证据；两者尚未组成统一证据流程。
- 已有专题分析包括行程/充电事件汇总、充电电气曲线、停车端点电量及温度、同类行程比较和归档质量。
- 尚缺统一逐字段的实际返回覆盖、有效新样本、变化情况、用途登记，以及按字段类型自动生成的历史分析视图。

## 下一阶段的具体交付

### 1. 数据利用总览

先针对明确时间范围、当前账号和车辆生成字段台账。逐字段列出：

- 是否出现、首次/最近观测时间、读取次数、新车辆时间的有效样本数、重复/修订/异常样本数。
- 空值、未返回、无效和待核实的分布；记录实际枚举原值种类、数值范围与观测变化。
- 解释依据、来源时间、适用车型；哪些页面展示、哪些分析消费、哪些仍缺用途。
- 状态分别为已用于分析、仅展示、待核实、样本不足、静态背景信息；多个状态可同时存在。

目录覆盖、实际返回覆盖、有效样本覆盖和分析使用情况分别计数。按时间区间明确分母，禁止将常量、无效值或同一缓存反复读取算作充分利用。
目录之外的新字段先在服务端识别和审核，保持公开接口的显式投影，不直接向前端展开原始负载。

### 2. 按类型复用分析能力

| 数据 | 合理用途 | 前置条件 |
| --- | --- | --- |
| 已核实数值 | 历史趋势、分布、极值、变化率、同场景比较 | 单位/换算可确认；使用有效来源时间；缺口不连接 |
| 已核实枚举/布尔 | 状态变化时间线、观测转换次数、连续观测区间 | 明确枚举含义；跳变时刻用采样边界表达，区间不冒充精确持续时间 |
| 待核实字段 | 原值变化分布、与已知事件的共同变化、人工实验候选 | 不把 0/1 猜成开关，不把共同变化写成因果 |
| 时间戳 | 新旧程度、延迟、更新频率、跨字段时间差 | 分开车辆时间、字段时间、云端读取时间与采集时间 |
| 档案和常量 | 配置/适用性判断、统计分组与解释背景 | 字段存在不证明本车已装配；不硬凑趋势图 |

分析优先使用已有归档，不增加车辆请求。缺失、无效、长期常量也提供数据质量和适用性信息。

### 3. 扩展有依据的场景分析

在实际返回率和语义证据核对后，依次评估：

- 座舱温度与空调状态的变化过程，比较不同外界条件下的观测表现。
- 四轮胎压/温度的长期变化和轮间差异，保留来源时间与有效样本。
- 低压电池读数随停车、行驶、充电场景的变化；不据少量缓存诊断电池健康。
- 门窗、门锁、灯光、座椅相关状态的变化记录和场景分布；仅对已核实编码给语义结论。
- 行程与充电专题关联同时段环境、起止 SOC、充电方式等有效条件，并显示比较样本数和覆盖差异。

是否实施每个专题，由真实可用样本决定，不以目录名称代替数据证据。

## 参数字典与实验室的定位

保留两类数据对象，串成「字段 → 历史 → 场景线索 → 实验摘录 → 人工核实」流程。
字典负责字段含义与核实状态，实验负责保存验证证据。可整合导航和字段详情，避免重复填写；不能只删入口就视为完成数据利用优化。
人工注释、研究结论与运行中的解码/提醒规则保持明确边界。

设计现已完成本地实现。最终功能、数据边界与验证结果见 [实现与验收](vehicle-research-implementation-2026-09-20.md)。本文件保留最初盘点口径；目录数量不代表实车数据覆盖。
