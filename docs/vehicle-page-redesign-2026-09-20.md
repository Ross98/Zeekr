## 1. 目标与现状

目标：车辆页完整覆盖所有可展示参数。默认进入“全部参数”，状态总览作为同页另一视图。已核实、待核实和未返回的字段均可查；不再仅选常用项、不要求跳去参数字典才能看全。

覆盖基线：当前词典共 237 个字段，其中 217 个 `private=false` 字段纳入全量目录，20 个私密字段沿用既有保护边界。这是词典覆盖数，不是本次实车返回数量，也不是车辆全部 ECU/CAN 信号数量。预览使用离线合成样例，45 项有示例返回，其余保留“暂无示例读数”。

现有实现已具备门窗三态、四轮对应、独立温度时间、PM2.5 单位待核实、详情折叠、夜间模式。`tests/ui_car.cjs` 本次离线运行通过；没有据此认定现有页存在已复现的功能故障。本方案主要处理信息层次和可发现性。

## 3. 页面顺序

1. **页头**：车辆标题、简短说明、刷新状态；外观选择沿用全局顶栏。
2. **同页视图**：“状态总览 / 全部参数 217”。默认全部参数；不是跳转到参数字典。
3. **刷新或连接反馈**：仅有失败、断开、旧缓存说明、刷新结果时出现；不遮挡既有数据。
4. **全部参数**：中文名或路径搜索、14 组选择、核实状态筛选；目录总数、示例已返回数、当前显示范围分开标注。
5. **状态列表**：中文名称与分组、解释后状态 / 读数、原始值、核实状态、来源时间；解释依据和路径可展开，主要状态不折叠。
6. **分页**：每页 20 项、已返回优先，显示当前范围及总数；所有 217 项可翻阅和检索，分页仅控制页面长度，不截断目录。
7. **状态总览**：保留门窗摘要、四门与锁止、四轮、座舱、详细依据，服务快速查看。

能源、充放电、低压电池、行驶、灯光等当前参数也收录到车辆页全量视图；充电曲线、地图、历史行程等分析交互继续由专页承接。参数字典仍用于术语、来源和复核，不能代替本页完整状态。

## 4. 桌面与手机布局

桌面保留现有侧栏和顶栏。全量视图使用清楚分栏的状态表，手机改逐条排列。总览视图中摘要横跨内容区，门窗在左，四轮与座舱在右；中等宽度改为门窗占整行，轮胎与座舱并排；小屏所有主卡单列。

- 桌面常用正文 14–16px，状态 13–14px，标题 17–29px；说明不小于 13px，技术路径 12px。
- 手机四门逐卡单列，保留明确左右 / 前后标签；四轮有足够空间时 2×2，320px 改单列。
- 手机不缩字强塞多列；刷新按钮、外观输入和详情摘要触控区域至少 44px。
- 预览内底部导航随内容显示；正式页面保留原有手机底栏并验证安全区和遮挡。
- 支持舒展 / 紧凑两种评审间距，默认舒展；仅评审变量，不新增正式设置项。
- 未配置车型时使用文字占位，不套用其他车型图。保留现有本车图片关联和图片原色。

## 5. 视觉与可读性

沿用当前浅色灰白 / 夜间深灰蓝体系，主强调保持青绿色。普通数值用正文色，已确认状态加勾，未知加问号，需留意加感叹号，颜色仅作辅助。未知不涂成故障红色，不把所有卡片染绿。

次要文字提高至足够对比度；不靠整块透明度淡化旧缓存或未知项。参数行允许长路径断行；胎压值与单位保持一组。通过内容重排解决窄屏，不用缩放整页图片解决。

## 6. 数据与解释契约

| 模块 | 已有数据来源 | 展示约束 |
| --- | --- | --- |
| 整车时间 | `model.updated_time / updated_at` | 展示数据年龄；不把读取时间当成车辆更新时间 |
| 四门 / 车窗 / 锁止 | `model.doors`、`model.lock` | 只用后端已解释结果；未知枚举不能被前端猜成已开 / 未锁 |
| 前舱盖 | `model.hood`，原值在字段列表 | 当前自动结果未知；本次人工确认独立标注 |
| 尾门 | `model.trunk` | 保留已验证关闭语义；非零不直接推断打开 |
| 胎压 / 胎温 | `model.tyres` | 按轮位匹配，kPa 与 °C，不混用座舱温度；缺失不补 0 |
| 车内 / 车外温度 | `model.metric_details / metrics` | 使用温度独立时间，不覆盖成整车时间 |
| PM2.5 | `fields` 中 `interiorPM25` | 合法非负数展示，0 有效；不使用等级码替代；单位未核实，不标“优 / 污染” |
| 原值 / 核实状态 | `model.fields` | 字段存在不代表设备存在；核实状态与数值分开 |
| 最近读取 | `state.read_at` | 刷新失败保留上次成功读取时间 |

门窗摘要统计 15 个解释槽位，不是 15 个独立故障，也不等同轮胎和座舱数据完整度。确认数只覆盖四门对应槽位，不把未知补齐。中控锁及四门门锁来自相关组合时，应按解释项展示，不声称多个独立传感器都验证过。

当前后端主要输出关闭 / 已锁 / 未知；“打开 / 未锁”尚未有本次新增的实车枚举规则。预览中的该场景明确标成展示演示；正式页须等现有已验证模型提供对应语义才显示。

胎压无已核对报警阈值，不作“胎压正常 / 偏低”判断，不新增安全评分。旧缓存提示只描述年龄，不推断车辆离线、休眠或故障。两小时前只是预览例子，实施应复用已有时间格式和新鲜度规则，另定阈值须有明确产品依据。

## 7. 交互

- **点未知 / 需留意入口**：展开与摘要对应的逐项清单；点条目滚到对应位置，用边框提示；键盘焦点保留可继续操作。需留意排前，未知排后。
- **点参数组**：原生折叠内容；刷新和切换外观保留展开状态，不强制跳回顶部。
- **全量参数**：分组和搜索同时作用，清空搜索 / 选择全部分组即可恢复完整目录。切换条件回到第一页；主题和刷新保留查询、分组与页码，字段路径作唯一标识，不按同名字段合并。详情只折叠说明与路径，不折叠当前值。
- **刷新**：沿用现有缓存读取、节流与结果语义：本地缓存复用、云端未变、获得新数据、更新时间未知。等待期间按钮禁用；失败保留原值和时间。
- **重新连接**：正式实现沿用既有本机连接恢复流程，不借连接恢复触发车辆控制。
- **切换外观**：复用现有系统 / 日间 / 夜间选择、持久化与多标签行为，不重新渲染业务内容或触发请求。
- **切换车辆**：若现有配置多车，继续使用原有选择入口；状态、图片、清单一起更新，不能沿用上一辆车的人工确认。

预览只演示本地交互；刷新按钮是模拟行为，未连接任何车辆、账号或服务。它不证明生产节流、持久化、多标签或数据请求已实现。
