# 通勤地点自动标注实施计划

依据：[通勤地点自动标注设计](../specs/2026-09-28-commute-auto-tags-design.md)。本计划只安排实现与验证；部署须在实现完成并经用户授权后执行。

## 1. 固定现状与测试基线

- 核对工作树、现有 `TripTags`、`PersonalStore`、`TrackStore`、`web.py` 的读写与登录边界。
- 在 `tests/test_trip_tags.py`、`tests/test_personal_store.py`、`tests/test_insights_api.py`、`tests/ui_trip_tags.cjs` 中先写失败测试；每项测试应验证用户可见行为或数据边界，不照抄内部函数。
- 记录现有测试总数及新测试的预期失败，再开始实现。

## 2. 私人规则与判定存储

- 在 `zeekr_control/personal_store.py` 中增加兼容旧库的事务迁移。新增账号、车辆作用域下的通勤规则版本和行程判定表；保留旧 `records`、`revisions`、`changes` 内容及语义。
- 规则版本记录中心点、各自半径、生效时间、启停状态、版本号。验证 WGS84 坐标和 100–1000 米范围。保存、暂停、恢复、删除均用服务端时间生成新版本，检查预期版本并调用现有会话守卫。
- 判定表以账号、车辆、行程 ID 唯一约束。存规则版本、匹配状态、端点采样时间与距离、人工排除状态。用原子插入及条件更新实现重复请求幂等。暂时性读取错误不落判定。
- 测试旧库升级、权限、越权、版本冲突、重复写入、人工排除与恢复后的行为。

## 3. 端点证据与判定器

- 新建聚焦的地点判定模块；从 `zeekr_control/tracks.py` 的本地 `observations` 只读获取行程时间窗两端各 180 秒内的有界采样。不得取中途点代替端点。
- 用缓存状态时间与 `trusted`、`plottable`、WGS84 条件筛选；明确区分“没有证据”“坐标系不符”“在圆外”“匹配”。球面距离比较两个独立半径，支持两个方向，禁止同地点往返误判。
- 测试边界等于半径、时间恰好 180 秒、跨午夜、反向行程、无轨迹表、损坏 JSON、不可信位置、非 WGS84、重复/晚到采样和不同车辆隔离。

## 4. 标签服务与接口

- 扩展 `zeekr_control/trip_tags.py`：读取月份时，按行程结束时间选取当时生效的规则版本，仅给未判定的新行程补做判定；保留既有手工 `tags` 记录。合并标签时去重，并返回“自动/手工”来源与证据不足的简短原因。过滤、同类比较和未标注计数使用合并后的标签。
- 定义“取消本趟自动通勤”独立操作；旧手工删除和撤销不改变自动判定。再次手工加入“通勤”按手工标签处理。旧 API 响应字段保留。
- 在 `zeekr_control/web.py` 扩展已认证私有接口，复用登录、同源、`insights_context`、会话守卫与错误格式。读取规则可与标签月查询合并；写规则及人工排除单独 action。无当前车辆绑定时不读写私有规则。
- 测试生效时间前行程不回填、规则修改和暂停不改历史决定、一次读取最多一条决定、并发写入、账号切换，以及 GET/POST 的认证与同源拒绝。

## 5. 地图设置界面

- 扩展 `zeekr_control/static/trip-tags.js`，在标签页顶部加入规则卡片。复用 Leaflet 与现有地图样式：点选家和公司、拖动中心点、显示两个半径圆、分别调节 100–1000 米；未保存前显示草稿，保存失败保留草稿。
- 加入暂停、恢复、删除及明确的确认文案；说明“首次读取新行程月份时自动判定”。显示自动来源和人工排除动作，手工标签输入及备注继续可用。
- 处理账号/车辆切换、离页、轮询重绘和迟到请求，销毁地图并丢弃旧上下文结果。保持键盘可操作及窄屏布局。
- 浏览器测试用合成轨迹验证点选、拖动、300 米初始圆、100/1000 米边界、保存/错误、来源显示、人工排除、切换上下文、暗色主题和窄屏；不调用真实车辆接口。

## 6. 文档、回归与交付

- 更新 `docs/web-usage.md`：选点、圆形判定边界、可调半径、往返规则、首次读取时机、证据不足与人工覆盖。
- 运行定向 Python 测试、相关浏览器测试、完整 Python 测试、`node --check` 与 `git diff --check`。若旧测试受新自动标签影响，核对语义再调整。
- 检查数据库迁移与回滚兼容：旧版程序应忽略新表；备份私人数据库再升级。不得输出真实坐标、账号或行程数据。
- 汇报实现结果、测试数量、真实地图/实车验证边界。按用户选择决定后续提交、部署或仅留本地审阅。

## 完成条件

设计文档的所有验收条款均有实现与测试证据；没有跨账号/车辆泄露；没有未经证据支持的自动标签；人工取消不被再次补回；已有标签功能继续工作。
