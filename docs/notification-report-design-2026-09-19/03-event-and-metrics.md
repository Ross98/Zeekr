# 03 · 事件、时间与统计

核心：冻结事件端点；停车确认期另记状态；统计只用独立有效观测。先设计清楚区间，才增加数值。

## 1. 当前行为与不变项

| 当前行为 | 代码锚点 | 本次要求 |

| 新鲜度180秒，允许车辆时间至多超前30秒 | `monitor.py:11,125–128` | 沿用；超限观测不进新统计 |
| 普通路径要求车辆时间严格递增 | `monitor.py:127–128` | 同缓存重复查询不计新样本 |

## 2. 建议存储与对象

### 2.1 版本化事件扩展

保留旧flat summary字段及其类型：`start_time/end_time/duration_seconds/distance_km/start_soc/end_soc/soc_delta/partial/battery_capacity_kwh`，以及既有私有地址字段。新增命名空间 `report_v2`。

| 建议子对象 | 保存内容 |
|---|---|
| `schema_version / metric_version / decoder_version` | 数据结构、公式及字段解释版本 |
| `profile_snapshot` | 此事件使用的容量、额定续航及标准/来源；在开始时冻结 |
| `start_snapshot / end_snapshot` | 对应事件端点的规范化参数及各自时间 |
| `parking_snapshot` | 仅trip_end有，候选终点后最后一条合格状态；独立时间 |
| `parking_changes` | 有证据的状态变化摘要、首次观察时间和是否存在缺口，不存无界日志 |
| `statistics` | 数值、单位、公式版本、来源和各项可用性 |
| `coverage` | 接受样本数、时间跨度、各指标覆盖、最大间隔、质量原因 |
| `comparison` | 已冻结的历史比较、样本数、候选event IDs、筛选版本及截止时间 |
| `attention` | 已冻结的提示项及其证据和等级 |
| `render` | renderer版本、正文是否冻结、降级项目、首次渲染时间、正文校验摘要 |

旧事件无report_v2即v1；不能据此说事件损坏。report_v2缺失字段默认未知。start/end snapshot只收字段白名单，不嵌整个raw、账户或车辆元数据。

新v2事件以开始冻结的容量作该事件估算，flat `battery_capacity_kwh`与report配置保持一致；这是新事件的明确口径。旧v1事件容量含义和已存值不改。活动v1会话升级没有开始配置时沿用其基础行为，但新高级指标标“升级后才有记录”，不拿后来配置冒充开始配置。

### 2.2 私有采样表

建议加表 `report_observations`：`vehicle_key, state_time, observed_at, normalized_payload, decoder_version`，唯一键`(vehicle_key,state_time)`；必要时另存规范化摘要用于诊断冲突。它不是公共轨迹表。

- 复用被 `Monitor.observe()` 接受的同一新鲜观测；同时间戳不因位置/内容变化而为报告增加第二个样本。
- 静止且无活动会话时，在私有monitor_state保留最近一份规范化观测，供下一事件取前一个起点。写样资格取“处理前有活动会话、当次新建会话、当次结束会话”的并集；不能只检查转换后的state.trip/state.charge。首次活动点、首次明确停止点、结算时接受的新状态都要写入，建事件时补入已有起点种子；统计仍按各自冻结区间筛选。重复缓存结算没有新样本，不例外增行。
- 一个观测可服务交叠的行程和充电区间，只存一次；按事件边界和所需状态筛选。不要两个循环重复累加。
- 参数行、活动状态和新事件在同一SQLite事务中更新；使用现有单执行者锁和唯一约束。不让断电造成累计器加过、采样没存，或反过来。
- 可以按表查询结算，也可持久化累计器；如用累计器，保存最后已处理state_time，恢复时幂等。最终结果须与同一观测集离线重算一致。
- 活动会话冻结report decoder/metric版本。升级后仅明确兼容的版本可继续同一指标；无法继续原规则时标`decoder_changed_mid_session`，保留两侧独立参数和版本，但受影响的跨版本差值、全程均值及历史比较不可用。不能用当前规则悄悄重解旧值。基础启停和flat摘要沿用原有行为，不因扩展指标失效取消事件。
- 不回填旧轨迹：`tracks.observations`只有定位/时间；最新`snapshots`是覆盖存储，不是历史。
- 使用现有700目录/600数据库约束。只存报告必要字段，不存Webhook、完整VIN、令牌或raw包。
- 本轮设计默认不自动删除已有或新增历史。预估并实测每条记录大小、日增长；摘要不塞全部样本，避免事件JSON无界增长。超过目标规模先报告实测结果，独立设计保留周期，不暗删用户数据。

### 2.3 历史索引

建议私有 `report_metric_index` 每个完成事件一行：event_id唯一、vehicle_key、kind、end_time、版本、完整性及经批准的比较数值。索引 `(vehicle_key,kind,end_time)`。与事件同事务写入；不包含地址、坐标或正文。

这是可重建的索引，不是真相源。重建只从已存事件得出，不能生成事件、重发消息或补出不存在的指标。首次只索引有v2契约的事件；v1继续供原页面使用。

## 3. 时间、采样与质量

### 3.1 三种时间

- `state_time`：车辆云端状态时间，决定事件端点/样本顺序。
- `observed_at`：本机收到时间，只说明何时看见，不代表车辆又更新。
- `event_created_at`：事件确认结算时间；用于冻结报告和“报告确认延迟”，不替代end_time。

温度另有field_time。其他字段默认只有envelope_time；不能说每个子字段都于同一毫秒实测。

数据新鲜度相对所描述状态的参考点计算。作为“停车后状态”给用户时，参考event_created_at：age>180秒写旧状态；不得借发送延迟重算并改写已冻结报告。实际首次发得很晚时，可在首次冻结正文时附“报告生成于X”，后续重试正文不变。

### 3.2 覆盖指标

| 指标 | 定义 |
|---|---|
| `accepted_samples` | 事件区间内被接受的独立state_time数；不含重复请求、不含终点后的停车等待样本 |
| `parking_samples` | 冻结终点后、结算前停车候选的独立新状态数 |
| `max_state_gap_s` | 区间内相邻接受state_time的最大间隔；不足2点为未知 |
| `max_observed_gap_s` | 同一对接受观测在本机observed_at上的最大间隔；不足2点为未知 |
| `max_observation_gap_s` | 上述两个最大值中的较大者；正文称最大观测间隔，有缺口时注明车辆状态或本机采集哪一侧导致 |
| `covered_seconds(metric)` | 相邻有效端点满足连续性时的时间间隔总和；每项单独计算 |
| `window_seconds` | 事件start_time至end_time；充电终点为首次确认停止观测，可能晚于实际停充 |
| `coverage_ratio(metric)` | covered_seconds/window_seconds；分母≤0则未知，不超过1 |
| `charging_time_coverage` | 连续且两端都明确活动的充电区间秒数之和/整场观测窗口秒数；不要求有可算功率，但要时间与充电状态有效；活动至停止的末区间不计入 |
| `quality_reasons` | late_start、sampling_gap、upgrade_mid_session、decoder_changed_mid_session、invalid_endpoint、charge_overlap、field_stale等明确原因 |

连续性要求：相邻车辆时间差 `0<Δt≤180秒`，两次本机observed_at间隔也在 `0..180秒`，两端值/模式有效且无矛盾。300秒低频期间的观测不能擅自按180秒内连续样本算；起点遗漏照实标注。

“独立观测43次”不是车辆每秒日志；覆盖率是上述采样规则的估计，不是数据完整性的绝对证明。零个有效区间的覆盖为0，有样本也不能假装100%。覆盖不包括事件观测前/后的真实未知时间。

### 3.3 无效或冲突处理

某字段无效只使该参数/指标失效，不能阻止基础通知。例如胎压缺失不使SOC失效，历史查询失败不使充电停止不发。影响事件端点和完整性的条件仍按现有状态机。

相同state_time改变内容但未被Monitor接受时，不替换报告已接纳样本；必要时只记诊断冲突。未来、倒退、过期数据不新增样本；查询失败不补零。

## 4. 行程终点与停车后状态

### 4.1 时间顺序

```text
09:18 开始行驶      10:00 首次下电      10:08 新状态      10:10 确认结束
      ├──── 行程统计区间 ────┤
                             ├── 停车候选观测 ──────────┤
                             冻结终点       独立停车状态     建事件/冻结报告
```

行程距离、耗时、SOC、续航、行程最高车速和行程温差只用09:18–10:00。10:08的锁车/门窗状态另标“停车后状态 · 10:08”。停车后SOC增加不得算进驾驶耗电；停车后胎温降低也不改写行程结束胎温。

### 4.2 停车候选更新

1. 创建trip.stop时复制冻结终点，建立parking候选；结束点不再覆盖。
2. 之后只有严格更新、被Monitor接受、未恢复行驶、动力仍明确下电的观测能更新parking_snapshot。确认期中充电可记录，但不改终点。
3. 每次替换整份停车快照；新快照某门窗缺失就未知，不从更旧快照补一个“仍关闭”。如需展示旧值必须单独注明原时间，不用于结论。
4. 用于“停车后状态”的观测即使曾在接收时新鲜，结算时超过180秒也标旧。重复旧缓存分支不更新parking_snapshot/parking_changes的时间。
5. 没取得更新状态：写“结束点状态 · 10:00；未取得更新停车状态”。不能写“10:10确认车辆仍已锁”。
6. 行驶/上电/状态机取消候选时清除该次停车候选结论；这段时间可能属于继续行程，已存参数保留，最终按新端点重算。不得丢掉或重复统计短停区间。

### 4.3 状态变化

- 有两端可靠状态且不同：写“10:04后续观测到已锁车”，可附前状态时间；不声称10:04就是锁车动作发生时刻。
- 前未知、后已锁：写“后续观测已确认锁车”，不能写“由未锁变为已锁”。
- 前后值相同：作为状态即可，不列重复变化。
- 中间有缺口：可写两端状态不同但“变化发生时间未确认”；不输出精确耗时。
- 只有最新可靠且在结算时新鲜的状态参与04提示；历史曾有注意状态但后来明确恢复时，提示移到变化说明，不继续置顶。

## 5. 行程与端点统计公式

表中门槛为设计默认，需版本化；不是厂商承诺。

| 指标 | 公式 | 展示条件/说明 |
|---|---|---|
| 记录距离D | odo_end−odo_start | 两端有效且D≥0；回退/缺失未知，不改用GPS补里程 |
| 时长T | (end_time−start_time)/1000 | T≥0；平均速度要求T>0；含途中等灯，不含最终停车确认等待 |
| SOC变化 | soc_end−soc_start | 有效端点；途中充电污染沿用现有失效规则 |
| 续航变化 | range_end−range_start | 有效同字段端点；叫云端续航增加/减少 |
| 容量估算耗电E | C×(soc_start−soc_end)/100 | C有效，SOC差非负且无充电污染；部分记录必须写区间估算 |
| 百公里估算 | E/D×100 | partial=false、D≥10km、SOC下降≥3个百分点、C冻结可用、无关键缺口/污染 |
| 全程平均速度 | D/(T/3600) | D有效、T>0；结果超出现有速度有效范围视为区间异常不显示 |
| 采样最高速度 | max(valid speed_i) | 至少1条合法速度；1条时标“仅1次有效车速观测”；不是真实最高速度 |
| 额定续航达成率 | D/(rated_range×SOC下降/100)×100% | 百公里估算同等里程/SOC/完整性门槛，额定range及标准冻结有效；不等于云端续航兑现率 |
| 车内外温差 | temp_end−temp_start | 两端独立field_time有效、不倒退，且各自state_time−field_time在[-30秒,180秒]；陈旧/缺时只给注明时间局限的单值，未来超限值不显示 |
| 胎压/胎温变化 | end−start，同轮同单位 | 两端合法、整车时间对应端点；说明没有轮胎独立时间。胎压0端点不算变化 |

平均速度不平均采样点的speed，也不使用原车avgSpeed字段。额定续航达成率>100%可如实显示，不裁成100%，同时标明标准和“基于SOC估算”。若纯数值离谱，先标数据异常，不靠裁值制造合理结果。

SOC为整数时短行程误差大，因此默认限制百公里值及历史能耗比较。即使阈值通过，也保留估算标签。显示1位小数不代表具有该精度。

充电污染是硬约束：`trip.charging_time≤冻结end_time`而旧摘要`soc_delta=None`时，可展示原始SOC两个端点，但不能由report快照再次相减恢复驾驶耗电、百公里耗电或达成率。高级统计继承`charge_overlap`，不得绕过旧保护。

## 6. 充电过程统计

### 6.1 端点、功率和平均值

充电start_time是首次接受的活动观测，end_time是首次接受的明确停止观测。实际开始可能更早、实际停止可能在两次观测之间。报告时长称“观测区间”，不声称精确桩计费时长。

同一观测、同一电气侧且直流活动明确：`P_i=U_i×I_i/1000`。有效电压>0、电流>0；电流负值、活动未知、非法字段不算。停止样本U/I可作为“停止观测值”展示，但不当活动功率。

对相邻两端都是有效活动样本且满足连续性的区间：

```text
区间权重 = Δt（秒）
区间功率面积 = (P_i + P_(i+1)) / 2 × Δt
观测区间平均功率 = Σ区间功率面积 / Σ有效区间秒数
最高采样功率 = max(P_i)
```

这是相邻观测的梯形近似，不证明间隔内真实功率曲线。平均功率默认要求≥3个有效功率样本、有效区间总时长≥120秒、覆盖率≥80%；否则省略均值并写覆盖不足。峰值可以在覆盖不足时显示，但加“仅N次有效观测”，不用于高质量历史比较。

覆盖分母为充电完整观测窗口start→首次明确停止；缺失区间、最后活动点至停止点均不外推、不补零。例：窗口46分钟，活动有效区间40分钟，覆盖87%。最后一个0A停止点不能无说明插入曲线拉低均值；两端都有效活动的区间才参与。

历史用的charging_time_coverage与功率覆盖分开：前者只要求两端确认活动及双时间连续；后者还要求同侧U/I与功率有效。两者都排除最后活动→停止区间，分母都含该观测窗口。用于历史用时比较时，另外要求最后两次观测在state_time和observed_at上的间隔均≤180秒，防止很晚才发现停止却被当作完整计时。

不要把容量估算充入量除以时长，称为“桩侧平均功率”。也不把上述功率面积积分结果称为计费电量；本轮不新增积分电量展示，避免与SOC容量估算混淆。

### 6.2 前后段变化

设计默认：按观测窗口的前20%与后20%时间段比较。两侧各有≥3个有效功率样本、≥120秒有效区间、各自覆盖≥80%，且全程记录完整、模式一致时才显示。

只取完全落入各窗口的合格相邻区间，不为跨界区间插值补功率；各自按时间加权算P_front和P_tail。若窗口太短、终点长时间无数据、任一侧条件不够，整项省略。

`下降比例=(P_front−P_tail)/P_front×100%`，P_front>0。下降≥20%才写“后段较前段观测功率下降约X%”；小于门槛不输出降速结论。20%是展示规则，不能解释为故障阈值。不猜原因是温度、桩限制、电网或车辆策略。

### 6.3 补电量、续航、目标

- SOC增加量=soc_end−soc_start；容量估算充入=C×增加量/100。SOC下降时如实列变化，不出负充入。
- 续航增加=range_end−range_start；受车辆估计影响，不保证可实际跑这段距离。
- 目标与剩余时间独立。剩余时间只说明当前车辆估计，不能反推出目标百分比。
- 开始/结束目标都有效且变化：写“目标70%→80%”；最终是否达成只比较结束时有效目标，不用开始目标。
- 因没有独立目标字段而未启用能力时，只写“目标电量暂未取得”；禁止把现场历史90%复用。
- 连接/原因/电池温度门控完全按02，不因已有停止事件就补全。

### 6.4 剩余时间与电池温度候选

剩余分钟在charging=true、取值0–2046且对应观测有效时，固定文案“截至HH:mm，车辆估计剩余N分钟”。预计结束=`state_time+N×60秒`；首次冻结正文时，只有该观测距冻结时刻在[-30秒,180秒]内且预计结束仍在未来，才加“约HH:mm结束，估计可能变化”。观测过旧时可保留带原时间的历史估计，不当发送时仍剩N分钟。2047、非法值、停止状态不提供剩余估计。重试不按新时钟改写这些行。

未来动力电池温度能力启用后，开始/结束都保存`pack_temperature`的对象/传感器、最高/最低/平均等统计口径、单位、独立时间。仅同传感器/同口径/同单位且两端独立时间均通过02校验，才给起止及差值。口径变化、缺时或陈旧时不出温差；现无可靠证据，三类报告均整项省略，不能借胎温或hvTempLevel填充。

## 7. 冻结与失败隔离

事件结算事务内冻结端点、统计、质量、提示和可用历史比较。纯计算输入不足、独立可选历史读取不可用时，可降级对应块并写基础事件。不得把SQLite写入/提交、磁盘或权限失败用宽泛异常捕获变成“字段缺失”：这些故障必须回滚本轮报告采样/活动状态/事件写入，并停止本轮投递；不能生成半套事件或在持久化失败后发送。能否继续事务不确定时同样回滚。基础采样发布等现有独立步骤不宣称被此事务覆盖。

地址只在第一次发送前按原事件位置解析，失败也冻结为未知。首次发送前把最终正文、renderer版本、裁剪结果原子保存；之后重试逐字节相同。禁止在发送阶段读取当前车辆状态、当前容量配置或后来新增历史事件重算报告。

开始通知不等后续曲线；停止报告可引用同一充电会话从开始积累的观测。两者是既有不同kind事件，不为了补字段增加第三条通知。
