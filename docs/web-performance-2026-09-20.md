# Web 性能与资源优化

范围：包含状态一致性修复，优化本地缓存查询。车辆采样频率、云端请求策略、页面轮询间隔、隐私白名单及业务统计口径不变。

## 基线与计划

使用 `python3 tests/benchmark_web.py`，临时目录和合成车辆，10,000 条事件，每条附带约 4 KiB 私有负载，重复 20 次。环境为本机 arm64、Python 3.9.6、SQLite 3.54.0。计时不包含建库；首页计时针对 `App.state()`，不包含 HTTP 序列化、网络或浏览器渲染。内存为单次调用的 Python 分配峰值，不等同于进程 RSS。没有访问真实车辆。

| 调用 | 中位耗时 | 每次 CPU 时间 | Python 分配峰值 |
| --- | ---: | ---: | ---: |
| 首页状态 | 93.037 ms | 91.056 ms | 44,527.1 KiB |
| 最近事件 | 70.462 ms | 67.860 ms | 44,520.1 KiB |
| 未变化快照恢复 | 0.105 ms | 0.115 ms | 13.9 KiB |

实施顺序：

1. 先补资源回归：长历史的查询内存、事件排序与损坏记录、快照修订和数据库连接关闭。
2. 事件按类型、车辆和排序索引读取；分页逐条处理，到达页容量即停止，保持按事件结束日期筛选。
3. 快照读取改为只读连接，未变化版本不搬运或解析原始负载；快照写入和充电读取显式关闭连接。充电统计逐条过滤历史，曲线仅保留公开投影与前一个解码样本。
4. 重跑相同基准、状态隔离测试、完整后端与浏览器回归；记录实测结果。

索引在监控初始化时幂等创建，兼容已有事件记录；仅增加查询索引，不删除或改写业务记录。首次启动创建索引需要少量时间及磁盘空间，规模随已有事件数量变化。

## 完成结果

回归结束后，独立运行同一基准：

| 调用 | 优化后中位耗时 | 优化后每次 CPU 时间 | 优化后 Python 分配峰值 |
| --- | ---: | ---: | ---: |
| 首页状态 | 0.596 ms | 0.632 ms | 32.5 KiB |
| 最近事件 | 0.110 ms | 0.117 ms | 25.4 KiB |
| 未变化快照恢复 | 0.083 ms | 0.093 ms | 4.9 KiB |
| 30 天充电统计 | 33.560 ms | 33.872 ms | 323.8 KiB |

首页状态的中位耗时及 CPU 时间约下降 99.3%。主要收益来自索引和停止全量读取历史，不是延长轮询周期。没有引入带过期时间的结果缓存；新事件和快照修订仍在下一次请求反映。

充电统计另做阶段对比：添加索引后、改为逐条读取前为 33.548 ms / 22,229.9 KiB；逐条读取后耗时基本持平，Python 分配峰值下降约 98.5%。统计仍扫描当前车辆历史以兼容旧记录的真实结束时间，CPU 不保证恒定；只保留统计窗口内的公开记录。曲线仍需保存公开点供原有降采样算法选择端点、峰值与缺口，输出上限保持 600。

## 验证与发布边界

- 新增 7 项资源测试：长历史的最近事件及首页分页峰值小于 1 MiB；统计过滤旧记录峰值小于 1 MiB；1,500 点合成曲线峰值小于 2 MiB；连接在请求成功和参数失败后立即关闭；未变化快照不解析原始负载；同时间修订可见；只读查询不初始化库且拒绝快照符号链接。
- `python3 -m unittest discover -s tests`：339 项通过，包含上一轮新增的 10 项状态一致性测试。
- 4 套 JavaScript 逻辑测试、10 套浏览器测试全部通过；包括事件分页、充电统计／曲线、参数核实、历史、行程、存储、主题和响应式布局。
- `git diff --check` 通过。代码复查保持既有日期、排序、车型隔离、部分记录与隐私投影语义。
- 以上为发布前的本地验收结果。已完成上线，服务器实际缓存比较、CPU／RSS 采样及回滚位置见 [发布记录](web-performance-release-2026-09-20.md)；不能用上述单次合成函数基准代替线上整体指标。
