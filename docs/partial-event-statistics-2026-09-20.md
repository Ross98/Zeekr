# 片段事件统计修订

用户要求：已发送事件中的部分记录也是真实观测，不能因为记录不完整而整条排除。

## 口径

- 主统计使用所有可见、已结束事件的有效已观测指标，含片段。事件按结束日期归期、每个事件 ID 读取一次；片段分项是主统计的子集，不重复相加。通知投递状态不决定数据有效性。
- 里程独立校验数值；时长必须与已记录起止时间一致，表示观测窗口，不能称为全程驾驶／实际充电时长。没有数据保留未知，有效零值保留零。
- 电量按事件保存的容量与一致的 SOC 端点估算。片段标记不再阻止估算；缺少起止时间、端点／容量无效、SOC 方向不符、充电混入驾驶、解码口径变化仍不估算。不能用当前车型配置补历史容量。
- 百公里估算继续使用同一批电量和里程有效的记录，要求至少 10 km、SOC 下降至少 3 个百分点；片段满足条件即可加入。所有均值均标明“记录／观测”，避免解释为完整行程均值。
- 周月报、每日趋势、标签比较、研究场景、账本每公里费用、充电统计与充电详情统一口径。最近记录的续航达成率也允许使用片段的有效端点，并明确标注仅代表该片段。研究场景按事件结束日归期，起点在范围外不再使事件电量失效；条件样本仍只取查询范围，保留范围不完整提示。
- 保留完整／片段标记及完整记录分项。只调整读取与呈现，不改已有事件正文、发送状态、数据库内容或通知流程。

## 实施顺序

1. 先写回归：完整 40 km + 片段 7 km = 已观测 47 km；仅片段也能统计；缺值、零值、异常端点与充电混入独立处理；历史已发送记录读取前后不变。
2. 在共享事件投影统一估算条件，充电统计与详情复用；修订各聚合分子／分母，保留完整与片段分项。
3. 更新页面标题、说明和浏览器断言，展示“片段已计入”，区分观测数据与全程推断。
4. 跑受影响测试、完整 Python 回归、周月报／标签／研究／充电界面检查，目视检查手机与桌面。

例如演示数据原完整里程 60 km、片段 7 km：主统计改为 67 km，记录平均为 67 ÷ 3 = 22.33 km；片段 7 km 已含在总量中，不再额外加一次。


## 实现与验收（2026-09-21）

初始修订基于 `58723ab`，分支 `codex/vehicle-research-ui`。已整合线上自动洞察并提交、部署运行代码 `02936dd`；未推送。详见[发布记录](partial-event-release-2026-09-21.md)。

- `usage_events` 统一校验数值、SOC 一致性、可比较电量变化与历史容量。总览／充电详情的估算由服务端提供，与统计同源；空估算不再由前端自行补算。
- 主里程、观测时段、每日趋势和记录均值纳入有效片段；完整分项保留。标签比较使用相同有效样本配对计算百公里值。账本每公里费用分母包含有效片段里程。
- 充电总量与每日电量无有效估算时返回未知；可靠零变化仍为零。片段满足条件可贡献估算电量和观测时段。进行中的会话继续单列。
- 续航达成率读取最近记录的有效端点；片段可计算，充电混入、解码口径变化、SOC 冲突等仍不作耗电推断。不回退到更早行程掩盖最近记录问题。
- 所有改动仅作用于读取／展示，保留历史事件内容、投递状态和尝试次数；已发送通知中的固化历史比较保持原样。现有账单中保存的事件快照亦保持原样。上线后重新读取历史统计即可使用新口径，无需重发事件。
