## 验证证据

固定 `package-lock.json` 对应 **Playwright 1.62.1 / Chromium 151.0.7922.34**。复用已安装的匹配 Playwright，先核对包版本与锁文件，再取该包 `chromium.executablePath()`，显式设为 `CHROMIUM_EXECUTABLE`；不是系统 Chrome。macOS arm64，`DESKTOP_ONLY=1`。

迁移后四组专项通过：状态、参数、轮胎、总览。状态/轮胎/总览覆盖两主题四桌面宽度，参数覆盖两主题三桌面宽度；没有改应用源码，没有运行无关后端全量，也没有操作实车、读取真实会话、发送通知或宣称生产验收。

在独立临时源码副本中做四个故障注入，每次恢复应用原文后只注入一种错误，均要求特定断言失败；工作区应用文件保持不变：

| 注入错误 | 检出的测试与信号 |
|---|---|
| 所有轮位错误使用第一轮数据 | 轮胎专项精确胎压断言失败，包含 `exact pressure` |
| 仅将“未核实值”误判为 safe | 状态专项全未知 15 项断言失败 |
| 两档车型俯视图都指向不存在资源 | 状态专项 `image.decode()` 失败，不能被单有 img 节点蒙混 |
| 502 刷新后悄悄把旧缓存时间改为现在 | 状态专项 `failed refresh retains` 全文保留断言失败 |

故障注入是合成验证，不代表线上有这些故障，也不是把旧 `ui_car` 实跑失败。日志、测试文件 SHA-256、锁定浏览器信息、退役旧源文件和四个注入结果保存在本机审计 `.git/local-work-audit/z11-ui-car-20261019/`。
