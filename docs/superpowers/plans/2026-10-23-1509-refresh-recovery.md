## 交付边界

先完成合成环境实现与测试；真实凭据存储、单次真实验证和生产启用分别有明确闸门。不能用真实账号试验旧 refreshToken 复用，不能发送测试 Bark。行驶数据优先，不引入轨迹补点或历史伪造。

## T1：协议结果和可选字段，先写失败回归

目标文件：`client.py`、`errors.py`、`query_policy.py`、`tests/test_client.py`、`tests/test_query_policy.py`。

- 新增独立 `gw2_refresh`：GW2 PUT，同 secure 路径，payload 只有 refreshToken；不带 line_login 的 identity_type。
- 登录结果可携带可选 refreshToken；缺失、空值、错误类型不破坏已验证的正常登录。未授权存储时不把真实值持久化。
- 请求返回 `QueryOutcome`，缓存命中与实际 status 请求可区分。QueryPolicy 未发送的拒绝有结构化证明；不从字符串推断。
- 刷新不递归重试，不缓存 Token 响应，不在客户端内部写会话；既有查询锁和共享 429 保护保持。
- 回归覆盖：PUT 签名与原始 body、无 identity_type、带／不带 refreshToken、缺字段／错身份／无效 JSON、429、超时、脱敏秘密和不返回完整响应正文。

验收：原读请求、短信和 JWT 路径继续通过；真实网络调用为零。

## T2：协调器与模拟秘密存储

新增：`credential_coordinator.py`、`credential_store.py`、`tests/test_credential_coordinator.py` 和仅用于合成测试的多进程 helper。

- 短文件锁＋持久占位，唯一 active_slot；身份含 op_id/PID/出生标识/boot 标识。
- 定义 provider 接口，先用临时目录模拟 provider；不得先替用户决定真实 Token 的存储位置。
- refresh_fp 单独记 eligible/executing/completed/uncertain/rejected；AT 变化或采集恢复不解禁同一 refreshToken。
- 活跃执行者不被启动扫描或超时误伤；存活状态未知不抢占。确认死亡后进入安全恢复，终态释放执行占位，不删除禁重放状态。
- 锁范围以断言和测试监测：凭据短锁／协调事务与 QueryPolicy 网络事务不重叠。所有分支含异常都释放锁与占位或留下可恢复意图。

多进程验收：用 barrier 与本地合成传输计数，两个刷新候选最多一次调用网关；失败者只重读当前会话。不能以“只写盘一次”代替请求计数。

## T3：提交与崩溃矩阵

先建立逐点故障注入，再实现恢复：

| 注入点 | 必须结果 |
| --- | --- |
| 占位前 | 不影响旧会话 |
| 意图提交后、调用前退出 | 无未发送证据时保守 uncertain；不重发 |
| 查询策略明确阻止发送 | 结束该操作，保留原资格及冷却 |
| 服务端已成功、响应丢失 | uncertain；旧 accessToken 成功也不解禁 RF |
| 收到成功、候选未保存前退出 | 无候选则 uncertain，不重复请求 |
| prepared 候选和回执存在、活动未替换 | 允许验证后只做本地提交 |
| 活动已替换、完成标记缺失 | 核对 expected_scope 和秘密引用，补完成，不毁掉新凭据 |
| 有新会话先行出现 | 旧操作 superseded，不能覆盖 |
| 保存、同步、权限或密钥存储失败 | 暴露存储错误，不以再次 refresh 掩盖 |

另测 PID 重用、存活执行者期限到达、下一次 1509、同 RF／不同 AT、响应不带新 RF、返回不同新 RF。旧记录不因重启或数据库迁移消失。

## T4：全部写会话入口接入

目标：`vehicle_login.py`、`cli.py`、`web.py`、`storage.py` 及对应测试。

- 短信挑战维持 10 分钟与既有速率／次数限制；发送挑战和等待用户输入不长期占位。
- 真正交换验证码／JWT 前重新领取和核对；会话已更新则不消费旧基线的交换请求。
- 延续同 userId 与绑定车辆校验。直接 CLI 保存及 clear 统一通过协调器。
- logout 遇活跃交换返回 busy；不复活会话；uncertain 执行已结束时可重新认证。
- 新身份／会话版本使旧异步结果失效，历史读取仍保持稳定账号归属。
- 全仓搜索审计真正写 `session.json` 的调用方，不能把普通健康 JSON 的 `storage.save` 一并加上凭据锁。

验收：refresh 对 refresh、refresh 对短信、refresh 对 CLI login/logout、挑战期间会话变化的确定性交错均覆盖；安全保存权限及无秘密日志通过。

## T5：中断事件与 monitor 接入

新增 `collection_incidents.py` 与测试；修改 `monitor_runtime.py`、`system_notifications.py`、投递／状态测试。

- 初始策略建议 3 次且 180 秒进入刷新候选，配置门禁默认关闭；没有可用 RF 时沿用现行退避与 10 分钟提醒。
- 原凭据实际目标 status 成功先自愈，不触发 refresh。仅在 eligible 且无活跃占位时刷新一次。
- 刷新完成、接口恢复、有效新状态出现分别持久记录；车辆列表成功／本机缓存不算接口恢复。
- uncertain/rejected 后保留受保护读取；本次事件的人工提醒只排队一次。不强制永久 blocked，不重发旧 sending/uncertain 通知。
- 新的采集中断不清除旧 RF 禁重放；过期云缓存不是当前实测数据。
- 原始返回先落盘，GPS 缺失不影响里程／SOC／速度观测，缺口标片段且第一有效轨迹点断开。
- 统计库故障不丢掉已经成功收到的行驶数据；协调库不可用时禁止交换但不强制停掉可安全进行的读取。

验收：连续故障／交错故障、暂停恢复、跨重启、旧 Token 自愈、刷新四分类、无 GPS、旧缓存、实际 status 成功但时间未推进、多个中断相继发生、告警防重均通过。

## T6：取消 256 限制的固定大小查询

目标：`snapshots.py`、`archive_reader.py`、`web._analysis_revisions()`、归档及异步查询测试。

- 新 `ArchiveScopeSelection` 从当前 scope/vehicle 的已验证关联得到稳定 owner，捕获注册库身份与成员 rowid 水位。
- 分片连接通过只读注册库索引关联建立固定大小 TEMP VIEW；删除按 alias 拼 UNION 的实现，不能只把 256 改大。
- 冻结成员和既有分片水位；查询中新增 scope 不混入旧查询。
- 改全部归档查询入口及缓存版本键；无账号关联则精确 scope，跨账号隔离不放松。
- 256/257/1024 scopes、跨月份分页、多条同时间、账号隔离、文件替换、旧无关联记录覆盖结果全集和查询计划。

验收：不报错且无遗漏／重复／越权；没有 scope 删除、原始 read 改写或历史数据迁移。失败则禁止开启自动 refresh。

## T7：存储选择与首次真实验证闸门

此任务须先取得用户选择和真实验证授权，不在准备阶段执行：

1. 用户选文件或钥匙串；实现对应 provider，更新隐私和备份说明，测实际后台访问权限／不可用行为。
2. 保持自动开关关闭；人工短信登录一次，只向诊断输出字段有无，按已选 provider 保存真实秘密。
3. 按完整占位协议只做一次真实 refresh，并用新凭据经查询保护读取绑定车辆；不试用旧 RF。
4. 核对提交回执、磁盘／钥匙串的活动凭据与状态；若 RF 未下发或刷新后没有不同的新 RF，明确不能据此重新启用旧值。
5. 真实验证成功不单独豁免其他测试、CI、备份和发布闸门；不宣称从此不存在接口停机或数据缺口。
