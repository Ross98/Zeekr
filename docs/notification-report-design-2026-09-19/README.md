## 3. 产品边界

- 通知事件仍是 `trip_end`、`charge_start`、`charge_end`。各发一条文本；不新增日报、周期状态推送或独立告警事件。
- 三类推送均优先呈现详细报告。参数可用就显示；核心字段未知要说明，未支持的选配参数按 01 的规则收束。
- 采集仍走同一个后台和现有查询策略。报告渲染、历史比较、补地址不主动请求车辆，不提高轮询频率。
- 本车字段规则不可推广为全部极氪车型规则。网页人工字段注释不自动进入生产解码。
- 不新增远程车控、驾驶评分、故障诊断、计费金额、公共分享页或手机无法访问的网页链接。
- 当前轮只新增此目录设计文件。运行时代码、私有数据库、车辆配置、已有未跟踪快照、原 `handoff.md` 均不因本轮设计而改动。

## 4. 经代码核对后的关键决定

1. **先隔离公开状态。** `EventStore` 有字段白名单，但 `monitor_runtime.read_status()` 会返回完整事件 `summary`，`WebApplication.state()` 将其带到网页。新增私有报告前先修这条暴露路径，并按当前选车过滤。
2. **保持现有事件时机。** `monitor.observe()` 的 `repeated_stop` 分支允许特定重复停车缓存在连续本机确认满十分钟后结算；现测试覆盖此行为。旧说明中“重复旧缓存绝不结算”已与代码不符。报告增强不可暗改状态机；重复读不算新状态、新样本或新的锁车确认。
3. **只确认已经确认的枚举方向。** 门/尾门 `0`、车窗位置 `0` 为关闭；其他值暂未知。不能用 `!=0` 实现未关提醒。锁车组合不匹配也不能直接写未锁。
4. **现有轨迹不够算详细统计。** `observations` 只存时间和定位，未保存速度、SOC、功率、胎压等序列。不能从历史路线数据库凭空生成旧报告的这些指标。
5. **停止不等于拔枪或达到目标。** 本车已观察到充电停止且枪仍连接时，连接字段仍为 `0`；非零桩侧电压也不能证明仍在充电。目标电量、停止原因、连接状态须独立证据。
6. **文本需控字节。** 当前发送器限制正文 UTF-8 为 2048 字节。完整数据留在私有事件，正文按重要性降级；不为长报告自动拆多条。
7. **回滚也要保住隔离。** 增强后的数据库不能交给仍完整透传summary的旧Web运行；回滚目标需保留P0隔离及正文冻结兼容。无兼容版本时停相关服务保留数据，详见05。
