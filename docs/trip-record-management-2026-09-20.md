# 行程记录管理：设计与验收

用户选择：错误行程移入回收区、可恢复，并从统计中排除。基线 `2876a14`，
分支 `codex/trip-record-management`。先本地实现与合成数据验收；不代用户挑选或删除真实记录，不自动部署。

## 行为

- 「行程与轨迹 → 本地记录」增加「管理行程」，可按日期范围查看正常记录/回收区；单条或多选操作。
- 执行前展示所选行程的时间、里程、片段标记与影响；显式确认后移入或恢复。预览过期、账号切换、记录变化或其他窗口已修改时拒绝执行。
- 仅管理已结束的本地行程。进行中、停车确认中、充电记录、其他车辆记录不可操作。
- 时间机、原始快照和全天采样保留；不改原始行程摘要、标签、位置或已发送通知。回收区行程不能通过普通单趟路线入口继续读取。
- 行程列表、最新行程、续航达成率、周月报、充电账本每公里估算、标签对比、日历与卡片素材排除回收区；恢复后重新纳入。
- 新生成通知报告的历史比较排除回收区；已冻结或已发送的旧报告不重写。
- 移入回收区取消尚未发送的通知；正在发送时拒绝操作，避免与发送过程竞争。恢复不重发历史通知。
- 选择、预览和错误提示在普通轮询中保留；切换账号/日期/来源时清除不适用选择，迟到响应不能覆盖新状态。

## 实现

1. 现有轨迹数据库增加行程回收状态、车辆版本与有界操作历史表，仅明确执行时创建；原始事件仍在原表。
2. 复用只读连接和公共摘要投影；统一 SQL 排除条件供事件、研究统计、续航和新报告比较使用。
3. 新管理列表/预览/执行接口复用网页登录、同源与请求密钥；提交前重核当前账号、车辆与会话。
4. 独立前端管理组件，接入现有行程页面；桌面/手机、日夜、键盘和状态反馈可用。

## 验收

- 测试先失败再实现：回收/恢复、持久化、批量原子性、账号车辆隔离、并发/过期/重复执行、通知取消且恢复不重发。
- 错误摘要、无结束时间、跨午夜、分页与空列表仍可辨认/管理；页面不输出身份、位置或私有通知正文。
- 所有关联统计和单趟路线同步变化，原始事件/采样/标签保留，旧数据库只读查询不迁移。
- 真实浏览器合成数据：单条/多选、预览取消/确认、回收区恢复、轮询与迟到响应、移动/日夜/200% 缩放。
- 完整 Python 与相关旧页面回归；检查差异、资源上限、兼容回滚影响。回滚旧代码会重新显示被隐藏记录，数据保留。

## 资源与兼容性

- 列表每页 20 条；日期范围最多 366 天；单次最多操作 100 条。预览有效 5 分钟，每个服务进程最多保留 32 份预览。
- 预览仅保留摘要指纹和公开字段，不缓存整批私有报告。单条摘要最多读取 2 MiB，扫描上限沿用 `UsageEvents.MAX_SCAN`；过大时明确拒绝。
- 仅执行回收/恢复时，在现有轨迹数据库事务内创建三张管理表；读取旧库不迁移、不新建缺失数据库。每辆车最多保留 1,000 条管理操作历史。
- 通知发送与管理操作通过数据库写事务和 `pending → sending` 条件认领协调。正在发送的记录拒绝回收；待发记录取消；恢复保留取消状态。
- 原始行程、采样、个人标签和已冻结通知保持原数据。回滚旧代码会重新显示回收区行程；已取消的待发通知不会自动重新排队。

复验入口：`python3 -m unittest discover -s tests`、`node tests/ui_trip_management.cjs`。浏览器沿用仓库的 Playwright 运行时及 `CHROMIUM_EXECUTABLE` 配置。合成预览服务可运行 `python3 tests/trips_fixture.py --management`；标准示例日期为 2024-01-02，分页示例为 2024-02-04。
