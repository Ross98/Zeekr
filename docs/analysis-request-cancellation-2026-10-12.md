# 慢分析请求合并与后台取消

## 范围和行为

本轮实现第 2 项：减少月历、报告等异步历史分析的重复计算，并让取消传递到后台。仍保留两个并发名额，没有增加生产内存或 CPU 配额。

服务端按账号、车辆、查询路径、排序后的查询参数、北京时间日期以及业务和归档数据版本合并正在运行的请求。每个等待者领取独立随机凭证，结果可分别读取。取消一个等待者不会中断其他等待者；最后一个等待者取消后，任务在协作检查点退出，关闭 SQLite 连接并清理临时文件，然后释放并发名额。已完成结果仍按原有 120 秒保留规则处理，不新增长期缓存。

取消检查覆盖归档分页、正文解压、分析临时表写入和遍历、事件读取、SQLite 长查询以及 JSON 序列化。SQLite 进度回调仅安装在异步分析线程，普通同步读取和定时报表不安装此回调。取消不是强杀线程，释放名额以实际退出为准；操作系统阻塞或不经过检查点的第三方调用不保证即时中断。

后台周期性检查账号和车辆绑定，变化后停止旧计算。停止轮询超过 30 秒的等待者过期，避免关闭页面、网络中断或取消请求未送达后长期占用名额；该期限是订阅租约，不是查询执行时限。正常轮询刷新租约。

前端月历、报告增加“停止分析”按钮。同条件读取期间重复点击保持当前请求。改变查询条件、切换页面或工具、切换账号、轮询超时以及超过整体等待期限时尝试撤销订阅。取消 POST 沿用登录、同源和请求密钥检查，服务端校验凭证所属账号和车辆。账号切换后旧凭证不能由新账号读取或取消，后台绑定检查负责停止旧计算。

日期编辑期间继续采用现有延迟重绘机制：后台取消已经发出，界面重绘等日期输入失去焦点后执行。没有设计或验证移动端布局。
