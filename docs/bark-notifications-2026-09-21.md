# Bark 状态提醒与企业微信详细报告

## 通道分工

- 开始充电：Bark 状态提醒，不发送企业微信详细报告。
- 充电结束：Bark 状态提醒；企业微信发送详细充电报告。
- 行程结束：Bark 状态提醒；企业微信发送详细行程报告和路线图片。
- 自定义提醒成立及恢复：优先 Bark；Bark 明确失败时由企业微信兜底。Bark 结果不确定时不兜底，避免重复通知。
- 存储异常及恢复：Bark 发送短提醒；企业微信发送完整存储详情。两通道独立记录和重试。
- 车辆接口返回 `1509`：不永久阻断，不立即要求重新登录。沿用查询锁与限流保护，以 60、120、240、300 秒退避，之后最多每 300 秒重试；进程重启保留同一会话的退避期限，实际 HTTP 429 仍遵守服务器冷却。成功读取后自动恢复正常采样并重置本次告警。连续失败至少 3 次且持续至少 10 分钟，才排队一次 Bark，说明仍在自动重试、期间记录可能不完整及最后成功读取时间；重启和不确定投递不重复发送。进行中行程／充电标记为片段，保留既有观测，停车结束需重新确认。脱敏网关原因保存在私有 `system-notifications.sqlite3` 的 `gateway_failures`（最近 200 条）及采集健康状态；不保存原始响应正文或凭据。网页显示脱敏原因。告警不依赖车辆会话，也不主动刷新车辆或发送测试消息。

车辆状态判定、报告计算、历史事件和企业微信图片发送逻辑不变。Bark 与企业微信的事件投递状态独立；一边成功后，另一边重试不会重复已成功通道。

## 私密配置

服务用户数据目录新增 `bark.json`，权限必须为 `600`，属主为 `zeekr-control`。文件不进入 Git、发布包或日志。

```json
{
  "base_url": "https://rocstarrobotics.com/bark",
  "device_key": "设备 Key"
}
```

默认路径：

```text
/var/lib/zeekr-control/Library/Application Support/ZeekrControl/bark.json
```

发送器只接受 HTTPS 地址和单行设备 Key。错误信息不会包含服务地址中的凭据、设备 Key 或 Bark 返回正文。

## 验收

1. 用合成事件验证开始充电只调用 Bark，行程结束和充电结束分别调用 Bark 与企业微信。
2. 验证 Bark 与企业微信单边失败不会重复已成功通道。
3. 验证自定义提醒只在 Bark 明确失败时调用企业微信。
4. 验证存储异常及恢复分别生成 Bark 短提醒和企业微信详情。
5. 用真实 Bark 配置发送人工测试消息，确认服务端返回 `code=200`，再由用户确认 Apple 设备实际收到。
6. 部署后检查两个服务、数据库新增表、私密配置权限和日志；不主动请求车辆刷新，不重发历史事件。
