# 企业微信用车报表 · 2026-10-07

## Overview

承接用户已批准的 Scriptable 样式：绿色大里程、四项指标、日期与记录状态。此文只记录报表这一个表面；全局产品与设计身份沿用现有项目。

先完成出图与手动推送逻辑；用户随后确认北京时间日报08:00、周一周报08:10、每月1日月报08:20，并明确要求启用。调度由服务器独立服务承担，提交、发布与启用结果在发布记录中单独核对。

## Colors

亮暗主题均为平面底色。accent 用于主里程，ink 用于数值，muted 用于标签、日期和时间，warning 用于部分数据与费用待补录。上方 token 来自 `zeekr_control/periodic_report.py` 的 `PALETTES`；修改配色须同时重建资产。

## Typography

构建字体为 Noto Sans SC，可变字体采用字重 500。标题（44px）、主里程（120px）、四指标数值（42px）、日期与指标标签（33px）、一般说明（30px）、警示（27px）。超长里程依次退到 90px、66px；指标数值可退到 30px。若仍溢出，拒绝出图并走文字兜底，不裁掉数据。

## Layout

固定 PNG 画布（1068 × 540px），检查图片自身，不声称已验证手机内实际收图效果。左上标题、右上报告日期；左侧主里程与行程/充电次数，右侧四指标为两列两行。下方状态与采样天数，底部车辆数据时间与生成时间。

左侧起点（50px），右侧指标起点（500px），列间距（267px），指标行间距（122px）。日期右对齐到 1018px。正文与动态文本均有宽度边界检查。

## Elevation & Depth

无渐变、阴影、玻璃或浮起卡片。靠留白、字级和颜色建立层次。

## Shapes

整张矩形图，无额外卡片边框、圆角容器或装饰图标。

## Components

- 主里程：绿色数值与 `km`；片段/缺项时显示“部分里程”。
- 四指标：估算耗电、观测时长、估算充入、充电实付。缺项对应指标标记“·部分”。
- 记录状态：暂无结束记录 / 部分数据 / 已结束记录汇总；未定价账单或未关联账单的充电结束记录追加“费用待补录”。
- 来源说明：`有采样天数/报告期天数`，车辆更新时间，生成时间。演示报表始终带“演示数据”。

## Do's and Don'ts

- 沿用大里程和四指标的既定层级；三个周期只替换标题、日期和数据。
- 保留缺失 `—`、已知 `0`、部分记录标记的区别。
- 采样天数只说明当天有观测，不能表达全天覆盖。
- 估算耗电与按账单日期归属的实付分开，不能把实付写成耗电成本。
- 示例只用于样式展示，不能作为真实用车或发送验收证据。

## 数据口径与实现

`periodic_summary.py` 只读取本地结束事件、归档元数据与个人充电账单。日期使用 Asia/Shanghai；日报为完整自然日，周报为周一至周日，月报为自然月。正式报告期必须已结束，边界为起点含、下一周期起点不含。跨午夜事件整体归属结束日。

里程、观测时长、估算耗电、估算充入来自结束记录。实付按账单 `date` 选取 `actual_cents`，以分求和后显示元；未定价账单与等待补账单单独标记。私人账单备注不进入输出。未结束行程不会被编成完整报告；“已结束记录汇总”也不等于全天数据完整。

`periodic_report.py` 负责视图、文字、图片及独立持久投递状态；`periodic_report_cli.py` 提供手动入口。运行时无浏览器、Pillow 或系统字体依赖。六张 RGB 底图与两套已着色字形由标准库 zlib 解压，逐行贴字，PNG 使用 zlib level 1 输出。构建方式见资产 README。

## 手动预览与发送

以下命令在项目根目录执行。预览输出须是不存在的新文件，父目录归当前用户所有且权限为 700；新建文件权限为 600。

```sh

python3 -m zeekr_control.periodic_report_cli --period week --date 2026-09-20 --theme dark --output /tmp/zeekr-report-preview/week.png
```

真实报告须显式 `--date`，且本地 session 有已确认车辆缓存；读取现有账号、车辆与归档，不轮询、不访问车辆云接口。`--session` 可指定 session 文件。默认只预览，只有 `--send` 才调用现有 `wecom-webhook.json` 配置；`--demo --send` 被拒绝。以下为操作说明，本轮未执行真实发送：

```sh
python3 -m zeekr_control.periodic_report_cli --period day --date 2026-09-15 --send
```

## 持久投递与失败边界

独立 outbox 为 session 同目录的 `periodic-reports.sqlite3`。账号范围、车辆、周期类型、起止日期构成去重键；首次调用冻结报表 payload 与主题。后续调用同一期使用冻结值，不因缓存或账单变化悄悄改报告。

先准备图片，再投递文字；文字成功才投递图片。图片准备失败仍投递文字。数据库先持久领取状态，再执行外部发送；并发调用通过条件更新领取，避免同一操作重复。

可重试图片准备失败及明确拒绝，最多 3 次，相隔至少 120 秒。间隔依赖未来调用；投递模块不自主睡眠；独立调度服务每30秒检查到期任务，持久状态决定是否处理剩余操作。永久拒绝、无效输入及缺资产停止重试。发送结果不明记 `unknown`；进程中断留下 `sending`，后续不自动重放，以免重复通知。文字已成功时只处理剩余图片。

## 定时任务

用户于2026-10-07明确要求启用。独立 `zeekr-reports.service`，实际服务用户zeekr-control，15% CPU/128MiB限制，30秒到期检查；不占用行程监控线程，不拉取车辆云接口。

- 日报：北京时间每天08:00，报告昨天。
- 周报：周一08:10，报告上周一至周日。
- 月报：每月1日08:20，报告上个自然月。

首次启用时间写入私有 `periodic-reports-settings.json`。启用前已错过的时点不补发；仅处理当天已到期且未超出6小时发送窗口的任务。重复启用不重置首次时间。断线重试最少120秒，发送不明/中断绝不自动重放，次日不会补历史积压。若超过窗口，需人工核对缺报原因。默认亮色，图片与文字使用同一个冻结报表。账户或车辆在统计期间变化，取消当前投递。

```sh
python3 -m zeekr_control.periodic_schedule --enable
python3 -m zeekr_control.periodic_schedule --status
python3 -m zeekr_control.periodic_schedule --disable
```

独立服务部署单元见 `deploy/zeekr-reports.service`。先用固定发布工具校验、切换代码；再从已部署、已校验提交安装该单元，启用私有设置并执行systemctl enable --now。发布工具已纳入此公共单元及资产manifest的精确白名单/输入哈希，并在后续备份、切换、回滚时停报表服务；只在支持报表的版本启动它。回滚到旧版保留投递数据，但不启动不支持的报表服务。

调度专项覆盖北京时间边界、十分钟错开、周一且月初同时到期、闭合日期、首次启用不追补、发送窗口、稳定账户去重、永久发送状态跳过统计、重试间隔、幂等启用及禁用不调用发送器。
