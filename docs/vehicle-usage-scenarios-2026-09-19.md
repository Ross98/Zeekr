# 用车场景与事件边界

依据：`notification-report-design-2026-09-19/`，以及用户新增的“开车回家后停车充电”和“目前正在交流充电”场景。既有设计仍决定字段证据、时间、消息预算与隐私；此文补充连续用车场景，不把缺少实车证据的能力算作已验收。

## 实施计划

1. 用合成序列验证驾驶、短停、长停、充电交叠和重新出发，先复现失败。
2. 修复移动证据未取消停车、短停观测漏算、未知充电观测被跨越、停车确认计时切换和途中补电统计问题。
3. 同一事件按冻结端点筛选观测；基础摘要与详细报告共用结算逻辑。
4. 跑场景回归和全部离线测试，检查事件数量、端点、统计、重启恢复与发送去重。
5. 读取后台已有的同期缓存核验交流充电。连接不可用或缓存过期时，明确保留未完成项，不能猜枚举。

## 回家后停车充电

假设已可靠识别充电，且停车期间动力保持明确下电：

| 时间 | 观测 | 应有行为 |
|---|---|---|
| 18:00 | 首次下电停车，SOC 45% | 冻结候选行程终点；开始十分钟确认 |
| 18:02 | 明确充电中，SOC 46% | 发一次充电开始；行程终点仍为18:00、45% |
| 18:10 | 连续停车确认完成 | 发一次行程结束；充电仍单独记录 |
| 次日01:00 | 首次明确停止，SOC 90% | 发一次充电停止；不凭90%声称充满或目标达成 |
| 次日08:00 | 拔枪、重新开车 | 只有可靠移动证据才开新行程；不另发拔枪通知 |

充电开始可能早于行程结束通知到达，这是十分钟确认规则造成的正常顺序。每份报告必须写自己的事件时间，不能把发送顺序当成真实发生顺序。若18:02仅插枪等待预约，不发充电开始；若充电无法可靠识别，就保持未确认。

## 场景矩阵

| 场景 | 规则与验收重点 |
|---|---|
| 正常通勤、回家直接停车 | 下电连续确认十分钟，单次结算，冻结首次停车端点 |
| 红灯、拥堵、等人但未下电 | 不结束行程，不把零车速等同停车完成 |
| 短停买东西、接人后继续开 | 十分钟内重新移动/上电取消候选；中间观测不丢、不重计 |
| 挪车、零速缓存但里程增长 | 连续新鲜里程增长也取消停车候选；以后一次停车作终点 |
| 停车后立即充电 | 充电与停车确认并行；停车后的SOC、续航、温度不污染行程统计 |
| 首条停车观测已在充电 | 无法拆分到家电量与补入电量，驾驶耗电不可用 |
| 途中短停补电后继续开 | 同一行程含充电，显示原始SOC端点，抑制驾驶SOC变化与耗电估算 |
| 高速服务区停留超过十分钟 | 满足停车确认则分成两次行程；充电独立记录 |
| 地库断网、云端不再更新 | 不因断网结束充电；保留活动会话，恢复后标数据缺口 |
| 新鲜停车观测随后转重复缓存 | 连续本机确认计时衔接；重复缓存不增加状态样本、不刷新锁车时间 |
| 断网后再次读旧停车缓存 | 真正的观测断档打断确认，不能拿墙上经过的时间充数 |
| 插枪、预约谷电、等待桩启动 | 插枪不等于充电；需要活动充电证据，预约码未核验时不猜开始时间 |
| 家用交流慢充 | 已据同期用户确认与两条新鲜缓存启用本车活动组合；停止/预约/插拔边界仍待核验 |
| 公共直流快充 | 沿用本车已核验的直流活动/停止组合 |
| 充电时暂时0A、未知或冲突状态 | 不虚构停止/重新开始；未知观测打断统计区间，不能跨过它插值 |
| 明确停止后再次开始 | 两次充电会话，各有稳定编号；不擅自推断停止原因 |
| 充电停止但仍插枪、次日才拔枪 | 停止只结算一次；连接状态未核验时保持未确认 |
| 充到目标、手动停充、桩断电 | 只在可靠停止证据出现时结算；原因和目标仍需独立证据 |
| 充电中人在车内、空调或动力状态冲突 | 不套用“忘记锁车”提醒；动力/移动冲突保持充电待确认 |
| 跨日、跨年充电 | 会话不按日期切断；时间显示明确日期 |
| 程序重启、通知失败重试 | 恢复同一会话，成功消息不重发，正文冻结复用 |
| 多车、时间倒退、过期或未来缓存 | 按车隔离；非法时间不推进状态、不生成新样本 |

“全部考虑”指显式列出行为与未知边界，不代表所有情况都有足够数据能自动判断。交流停止、插枪、预约、目标、原因没有核验前，不以直流样本替代其实车验收。

## 交流充电证据清单

用户于本轮明确确认正在交流充电；随后读取后台两条新鲜缓存，已核验活动组合，见[交流充电补证](ac-charging-validation-2026-09-19.md)。该证据不包含充电停止和插拔过程。

- 先读取后台已经采集的、当前绑定车辆的私有快照，核对`updateTime`和读取时间；过期快照不能与“现在”配对。
- 仅提取充电口盖、充电状态、充电器状态、连接字段、交流/直流电压电流、SOC、剩余时间、动力状态及车速有效性。原始车辆身份、位置、会话和服务器信息不入Git或聊天。
- 分别核验正在充电、预约等待、停止但仍插枪、拔枪四种状态。一个活动样本不能证明停止、连接或预约枚举。
- 通用`chargeUAct/chargeIAct`的测量侧、相数和功率口径未明确时，不标成桩侧功率，也不默认用两数相乘冒充交流输入功率。
- 不为取样主动停充、拔枪、唤醒车辆或提高轮询频率；后续自然出现的状态再单独核验。

## 本轮离线验收

`python3 -m unittest discover -s tests -q`：230项通过。新增12项连续用车场景和9项交流解码测试，另有报告/Web回归；测试使用临时数据库、合成车辆及假发送器。`git diff --check`与前端JavaScript语法检查通过。

已修复停车后里程增长未取消候选、短停样本丢失、未知充电间隔被跨越、混合新旧缓存确认重置、途中充电SOC被重新计算，以及整数分钟/百分比末尾0被删的问题。停车候选样本单独有界保留，续行时才合回行程，避免长行程样本被最终停车等待挤掉；真实采集断档仍重新等待十分钟。

交流活动识别已通过本车同期缓存补证，但停止/预约/插拔等尚未实车验收，不能把离线通过声称为全部实车场景完成。
